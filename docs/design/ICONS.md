# Иконки: каталог и происхождение

Командные иконки, иконки файлов и знак приложения выполняют разные роли и берутся из разных источников. Визуальный лист: [icon-sheet.png](icon-sheet.png) (исходник [icon-sheet.svg](icon-sheet.svg)), сборка — `python3 scripts/design/render-icons.py`.

## Команды и навигация — `src/SSHExplorer.App/IconCatalog.cs`

Каталог — единственное место, где за названием команды закреплён рисунок. Для каждого элемента указаны ключ, назначение и источник. Общий контракт:

- сетка 16 DIP, штрих 1 DIP (1,25 DIP от 19 DIP и крупнее);
- скруглённые концы и соединения;
- цвет наследуется от `TextElement.Foreground`, поэтому hover, disabled и High Contrast получаются автоматически.

| Источник | Количество | Лицензия / условие |
|---|---:|---|
| Segoe Fluent Icons (запасной шрифт — Segoe MDL2 Assets) | 33 глифа | Системный шрифт Windows. В комплект не включается, рисуется установленной Windows. Code points сверены со [списком Microsoft](https://learn.microsoft.com/en-us/windows/apps/design/iconography/segoe-fluent-icons-font) |
| Собственные векторы SSH Explorer | 21 | Нарисованы для проекта, на тех же условиях, что и исходный код репозитория. Path data одна и та же для WPF и листа |

Собственные векторы закрывают команды без подходящего системного глифа или с вводящим в заблуждение глифом:

- восемь режимов просмотра: огромные, крупные, обычные и мелкие значки, список, таблица, плитка, содержимое;
- все вкладки и новая вкладка;
- документы и передачи;
- сервер, процессы, производительность, терминал;
- выключение, перезагрузка, переподключение;
- сеть, хранилища.

Исправленная ошибка beta.5: «Мелкие значки» использовали `U+E80B` — это CallControl (телефон). Теперь режим показывает две колонки строк «значок + имя», как в Проводнике.

## Файлы и папки — `SystemFileIconProvider`

Без изменений с beta.5. Используются ресурсы установленной Windows (`SHGetFileInfoW` с `USEFILEATTRIBUTES`, `SHGetImageList`, 16/32/48/256 px). Файл ради иконки не скачивается. Кэш общий, есть нейтральный fallback и overlay ссылки. Ресурсы Windows не распространяются. Rust-прототип использует тот же подход: системный image list по расширению.

## Знак приложения

Открытая синяя папка, спокойный голубой задний лист и светлый символ терминала `>_`. Без букв, бликов и мелких украшений. Знак оригинальный, нарисован для проекта, на тех же условиях, что и исходный код репозитория. Сторонних изображений и шрифтов не содержит.

| Файл | Назначение |
|---|---|
| `assets/brand/app-icon.svg` | Мастер для 64–256 px |
| `assets/brand/app-icon-32.svg` | Оптический вариант 32–48 px: толще штрих, проще перспектива |
| `assets/brand/app-icon-16.svg` | Оптический вариант 16–24 px: силуэт без внутренних деталей, усиленный `>_` |
| `assets/brand/png/app-icon-*.png` | Отрисовка каждого размера из своего варианта, не масштабированием |
| `src/SSHExplorer.App/Assets/AppIcon.ico` | 9 изображений: 16, 20, 24, 32, 40, 48, 64, 128, 256. До 48 px — 32-bit DIB (прозрачность в альфа-канале, AND-маска нулевая), крупнее — PNG |
| `scripts/design/build-app-icon.py` | Воспроизводимая сборка PNG и ICO из SVG |

Где используется:

- `ApplicationIcon` EXE: Проводник, панель задач, Alt+Tab;
- `AppIcon.Apply` для каждого окна;
- «О приложении»;
- Rust-прототип через собственный ресурс `RT_GROUP_ICON`.

Фактическая иконка собранного EXE извлекается в CI (`windows.yml`, `rust-prototype.yml`). Для beta.6 это ещё не выполнялось. На Windows иконка может кэшироваться Проводником: проверяйте на новой распакованной папке.

Финальная эстетическая приёмка знака и командных иконок — за пользователем.
