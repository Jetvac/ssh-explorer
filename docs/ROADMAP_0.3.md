# План 0.3: подключение, передачи, сервер, терминал, мелкие улучшения

Дата: 04.11.2026. База — ветка `claude/beta6-ui-rework` (Windows CI зелёный, beta.6 не выпущена по решению пользователя). Работа ведётся в ветке `claude/0.3-features`.

Выбраны группы **A, B, C, D, F**. «Сервер как диск Windows» (E) отложен.

## Принципы

- Каждая фаза заканчивается зелёным Windows CI и коммитами по законченным изменениям.
- Логика — в `SSHExplorer.Core`, с тестами без окон (Windows CI и Linux core workflow). Окна проверяются только в CI (`--beta6-ui` и последующие режимы), не на рабочем столе пользователя.
- Проверки измеряют результат (геометрия, байты, состояния), а не наличие элемента.
- Опасные действия (службы, туннели, архивы с перезаписью, chmod рекурсивно) — с тем же явным подтверждением, что питание сервера: сервер, адрес, точная команда, без повторной отправки.
- Ограничения SSH.NET 2026.0.0 учитываются явно: прокси только SOCKS/HTTP, агента нет — свои реализации поверх открытых точек расширения.

## Фаза A — подключение

| # | Фича | Решение | Проверка |
|---|---|---|---|
| A1 | Импорт `~/.ssh/config` | Парсер подмножества OpenSSH: `Host` (шаблоны `*`/`?`/`!`), `HostName`, `User`, `Port`, `IdentityFile` (`~`, `%d`, `%u`, `%h`, `%r`), `ProxyJump`, `ConnectTimeout`, `Include`. Первое значение побеждает, как в OpenSSH. Неподдерживаемые директивы показываются, не молча теряются. Диалог импорта с предпросмотром и выбором | Core-тесты разбора и порядка; UI: диалог с фикстурой |
| A2 | Ключи из SSH-агента | Протокол агента (request identities / sign request, флаги rsa-sha2-256/512). Транспорты: OpenSSH Agent Windows (`\\.\pipe\openssh-ssh-agent`), Pageant (named pipe, затем WM_COPYDATA). `IPrivateKeySource` с `KeyHostAlgorithm` и своей `DigitalSignature` — приватный ключ не покидает агент | Core: свой агент-эмулятор на потоке; Linux: настоящий `ssh-agent` через unix socket + OpenSSH fixture |
| A3 | ProxyJump | Сессия jump host с собственной проверкой host key → `ForwardedPortLocal` на `127.0.0.1:0` → целевое подключение через локальный порт, host key проверяется по имени **целевого** сервера. Цепочки до 3 узлов. Один профиль может ссылаться на другой как на jump host | Linux core: два OpenSSH-контейнера/VM, цель недоступна напрямую |
| A4 | Группы профилей | Поле «Группа» в профиле; на «Главной» — группировка и свёртывание, поиск по группам | MVVM и UI-геометрия |
| A5 | Импорт из PuTTY/WinSCP | PuTTY: реестр `HKCU\Software\SimonTatham\PuTTY\Sessions` (только чтение). WinSCP: `WinSCP.ini`/реестр. Пароли не импортируются | Core-тесты разбора фикстур |

## Фаза B — передачи

| # | Фича | Решение | Проверка |
|---|---|---|---|
| B1 | Докачка | Собственный `.sshexplorer-*.part` с манифестом (источник, размер, mtime, хеш первых/последних блоков). Повтор продолжает с проверенного смещения; при изменении источника — начинает заново и объясняет | Core: обрыв на середине, изменённый источник, чужой `.part` не трогается |
| B2 | Скорость и параллельность | Настройки: число одновременных передач (сейчас фиксировано 2) и лимит скорости (токен-бакет на поток) | Core: измеренная скорость в пределах лимита |
| B3 | Сравнение папок | Локальная ↔ удалённая: размер, время, опционально хеш. Результат — список различий; копирование только выбранного после подтверждения | Core + UI таблица |

## Фаза C — работа с сервером

| # | Фича | Решение | Проверка |
|---|---|---|---|
| C1 | Архивы | Упаковать/распаковать tar.gz/zip на сервере, если есть `tar`/`unzip`/`zip`. Распаковка — в новую папку, без перезаписи по умолчанию; аргументы экранируются, имена файлов передаются как данные | Linux core: реальные архивы, имена с пробелами и `-` |
| C2 | Службы systemd | Раздел «Службы»: список, состояние, автозапуск; запуск/остановка/перезапуск с подтверждением и определением прав как у питания | Linux core на systemd-VM; UI на фикстуре |
| C3 | Журналы | `journalctl -u` и `tail -F` файла в отдельном просмотре: хвост, пауза, фильтр, лимит буфера | Core: потоковый разбор, отмена |
| C4 | Поиск по содержимому | `grep -rIl`/`-n` с лимитами и отменой; результаты открываются в файлах | Linux core |
