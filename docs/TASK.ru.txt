Ты — ведущий разработчик Windows desktop приложений, архитектор SSH/SFTP-клиентов и специалист по интерфейсам Windows 11. Разработай полноценное приложение для повседневной работы с Linux-серверами: подключения, интерактивный терминал, графический диспетчер задач и файловый менеджер с поведением и оформлением Проводника Windows 11.

Рабочее название: **SSH Explorer**. Основная платформа клиента — **Windows 11 x64**. Интерфейс — русский. Серверы — Ubuntu, Debian и другие Linux-системы с уже настроенным SSH. Приложенные скриншоты Проводника и Диспетчера задач Windows 11 являются основными визуальными референсами.

Результат работы — исходный код, воспроизводимая сборка, запускаемое приложение `.exe` и проверенная самостоятельная поставка. План и прототип являются промежуточными результатами. Продолжай работу до выполнения требований, исправляй найденные дефекты и сообщай о реальных блокерах.

### 1. Обязательные ограничения

1. Приложение работает локально на компьютере пользователя. Подключения к серверам идут напрямую через SSH. Облачный посредник, отдельный веб-сервис и открытие дополнительных портов на сервере не требуются.
2. На управляемый сервер нельзя устанавливать пакеты, агенты, службы, контейнеры, интерпретаторы, библиотеки или собственные исполняемые файлы. Нельзя изменять `sshd_config`, `sudoers`, shell-профили, cron или systemd для обеспечения работы приложения.
3. Файловые операции выполняются преимущественно через SFTP внутри SSH. Это соответствует требованию «полностью через SSH». Для полного файлового режима на сервере должна быть доступна существующая SFTP-подсистема. Проверяй её наличие; при отсутствии сохраняй доступные функции и объясняй ограничение без автоматической установки или перенастройки сервера.
4. Для терминала и мониторинга разрешены SSH shell/exec, чтение `/proc` и существующие системные команды. Короткие ограниченные команды через имеющийся `/bin/sh` допустимы; постоянный сборщик, фоновый демон и загружаемые на сервер служебные программы запрещены.
5. Пользовательские операции с файлами и необходимые временные файлы передачи допустимы. Они не должны превращаться в скрытую установку компонентов приложения на сервер.
6. Пользователь запускает `.exe`. От него не требуется устанавливать Python, Node.js, npm, .NET SDK, отдельный .NET Runtime, Windows App SDK Runtime, Visual Studio, WSL, PuTTY или `ssh.exe`. Все необходимые зависимости поставляются вместе с приложением либо обеспечиваются комплектным автономным установщиком. Сборочные инструменты нужны только разработчику.
7. Обязательна самостоятельная поставка с `.exe`; файлы библиотек рядом допустимы. Единственный физический EXE без распаковки зависимостей не является отдельным требованием. Не подменяй автономную поставку сборкой, работающей только на машине разработчика.
8. Все данные интерфейса должны поступать от реальных серверов. Демонстрационные данные допустимы только в явно изолированном тестовом режиме. Не показывай работающими операции, которые ничего не выполняют.
9. Доступ выполняется с правами выбранной SSH-учётной записи. Права администратора на Windows для обычной работы приложения не требуются.

### 3. Стек и архитектура

Базовый вариант: **C#, актуальная стабильная LTS-версия .NET, WinUI 3 / Windows App SDK, MVVM, поддерживаемая SSH/SFTP-библиотека**. SSH.NET рассмотри первой. Версии выбирай по текущей официальной документации и совместимости, затем фиксируй в проекте. Не используй preview-компоненты без конкретной необходимости.

Для терминала нужен полноценный эмулятор. Практичный вариант — локально упакованный xterm.js в изолированном WebView2; основное приложение и файловый интерфейс остаются WinUI. Это не должно требовать Node.js, браузера пользователя, внешнего CDN или локального HTTP-сервера. При использовании WebView2 обеспечь комплектный Runtime для автономного запуска, например Fixed Version, и задокументируй его обновление.

До построения всего интерфейса проверь небольшой работающий вертикальный срез: запуск опубликованного EXE, проверка host key, SSH-вход, PTY с resize, реальная SFTP-папка, перетаскивание файла из Windows и обратно.

Одновременно выбери и проверь виртуализированную таблицу с колонками, выделением и клавиатурой: наличие DataGrid в WPF не означает наличие того же компонента в WinUI. Выясни ограничения выбранных библиотек и упаковки на этом этапе. Если стек требует изменения, обоснуй его техническими результатами и сохрани все пользовательские требования.

Раздели ответственность:

- Представление и состояние экранов.
- Управление серверными сессиями.
- SSH transport.
- Хранилище доверенных ключей и хранение секретов.
- Файловые операции и передачи.
- Терминал.
- Мониторинг.
- Настройки и журнал диагностики.

Не усложняй архитектуру сервисами без необходимости.

Одна вкладка владеет отдельной логической серверной сессией. Внутри допустимы несколько SSH-соединений или каналов, если этого требует библиотека: терминал, SFTP, команды мониторинга, передачи. Не обещай один TCP-сокет там, где библиотека этого не обеспечивает. Все соединения проходят одинаковую проверку ключа и закрываются вместе с владельцем.

Длительные операции выполняются вне UI-потока, с таймаутами, отменой и ограничением параллелизма. Изоляция терминала, мониторинга и передач должна предотвращать блокировку всего интерфейса одним медленным запросом. Поздний ответ старой навигации не должен заменять содержимое уже открытой другой папки.

Ориентиры:

Сохраняй компактность рабочего инструмента. Главная показывает список серверов. Не заменяй файловый интерфейс крупными карточками и декоративной панелью статистики. Системная рамка, изменение размеров окна, Snap Layouts, масштабирование DPI и фокус должны работать предсказуемо.

### 5. Главная, профили серверов и доверие SSH

Закреплённая вкладка «Главная» содержит все сохранённые серверы в виде списка с поиском и сортировкой. Показывай пользовательское имя, адрес, порт, пользователя и состояние активных сессий. Неподключённый профиль не называй недоступным без реальной проверки.

Добавление, изменение, удаление и подключение должны быть доступны из понятных кнопок и контекстного меню. Удаление профиля удаляет локальную запись, а не данные сервера.

Профиль содержит стабильный ID, имя, DNS-имя или IPv4/IPv6, порт SSH, логин, способ входа, путь к приватному ключу при необходимости, стартовую папку и настройки подключения.

Обязательны пароль и приватный ключ, включая зашифрованный ключ с passphrase. Поддержку keyboard-interactive реализуй, если её требует выбранный способ аутентификации. Использование локального SSH-agent можно добавить отдельно; проброс агента на сервер по умолчанию выключен.

**Пароль, приватный ключ пользователя и host key сервера — разные сущности. Под отпечатком сервера понимается отпечаток его SSH host key.**

При первом подключении до передачи пользовательских секретов покажи адрес, порт, алгоритм и SHA-256-отпечаток серверного ключа. Предложи доверить и сохранить, доверить только для текущей сессии или отменить.

Храни подтверждённый публичный ключ и его метаданные в собственном хранилище приложения с привязкой к endpoint и алгоритму. Название профиля не должно служить идентификатором доверия.

При последующих соединениях проверяй ключ обязательно, включая SFTP, фоновые соединения и повторное подключение. Изменение ранее доверенного ключа блокирует соединение и показывает старый и новый отпечатки.

Замена доверенного ключа возможна только отдельным явным действием пользователя после проверки. Новый алгоритм или ключ не должен становиться доверенным автоматически. Не отключай проверку и не меняй системный `known_hosts` без отдельного пользовательского действия.

Объединяй одновременные запросы доверия к одному ключу; разовое доверие действует только для соединений текущей логической сессии.

Сохраняй секреты только по выбранной пользователем настройке, используя Credential Manager или DPAPI CurrentUser. Обычные настройки содержат ссылки на секреты, а не открытые пароли. Не записывай секреты, введённые пароли и содержимое ключей в логи, экспорт профилей или репозиторий. Экспорт профилей, если реализован, по умолчанию исключает секреты.

### 6. Вкладки и жизненный цикл

Открытие сервера создаёт новую вкладку с заданным пользователем именем. Повторные независимые сессии одного сервера допустимы; различай их небольшим номером, сохраняя исходное имя. Подсказка показывает endpoint и пользователя.

Поддержи переключение, закрытие, перестановку вкладок и разумное поведение при их большом количестве. Кнопка «+» открывает выбор сохранённого сервера с возможностью добавить новый.

В каждой серверной вкладке слева находятся «Терминал», «Диспетчер задач», затем файловая навигация: домашний каталог, корень доступной файловой системы, закреплённые каталоги и раскрываемое дерево. Узлы появляются по результатам чтения сервера; не рисуй вымышленные `/home`, `/etc` или другие папки без проверки. Учитывай SFTP chroot.

Переключение разделов сохраняет терминал, текущий путь, выделение, вид и историю. Переход на другую вкладку не пересоздаёт соединение.

Состояния сессии: подключение, ожидание доверия или аутентификации, подключена, потеря связи, переподключение, закрывается, закрыта. Ошибка содержит понятную причину и доступное действие.

Крестик закрывает именно сессию: отменяет задания, останавливает опрос, завершает локальные циклы чтения и освобождает SSH/SFTP/PTY и связанные ресурсы. При активной передаче предложи отменить закрытие либо прервать передачу и закрыть. Не оставляй скрыто работающую сессию после исчезновения вкладки. Для бездействующей вкладки лишнее подтверждение не требуется.

При обрыве связи сохрани видимый контекст и пометь данные устаревшими. Повторное соединение заново проверяет ключ. Команды терминала, удаление и другие изменяющие операции автоматически не воспроизводятся. История терминала может остаться на экране, но новый shell обозначается как новая сессия.

Закрытие SSH не означает гарантированное завершение всех удалённых процессов, запущенных пользователем. Не обещай такого поведения для `nohup`, служб и других отсоединённых задач. Завершаться должны принадлежащие клиенту соединения и служебные запросы.

### 7. Интерактивный терминал

Реализуй настоящий SSH shell с PTY, а не последовательное выполнение команд из текстового поля.

Нужны ANSI/VT, UTF-8 и кириллица, цвет, курсор, scrollback, выделение, копирование и вставка, поиск по буферу, управление размером шрифта, альтернативный экран и изменение размеров PTY вслед за окном.

Проверь команды и интерактивные программы: shell completion, Ctrl+C, Ctrl+D, Ctrl+Z, `less`, `nano` или `vim` при наличии, `sudo` с интерактивным вводом, `top` и установленный `htop`. Заявляемый TERM должен соответствовать возможностям эмулятора. Передача байтов и декодирование не должны повреждать символы на границах блоков.

Горячие клавиши файлового менеджера не перехватывают ввод активного терминала. Для копирования и вставки терминала предусмотрены Ctrl+Shift+C / Ctrl+Shift+V. Многострочная вставка обрабатывается с bracketed paste, а при необходимости показывается подтверждение перед отправкой потенциально исполняемого многострочного текста.

«Открыть в терминале» для каталога открывает отдельный терминальный контекст с этим рабочим каталогом, принадлежащий той же серверной сессии. Не отправляй `cd` в уже работающую интерактивную программу и не меняй shell-профили ради синхронизации каталога. Дополнительные терминалы также закрываются с серверной вкладкой.

Если применяется WebView2, загружай только комплектные ресурсы, ограничь IPC, внешние переходы и доступ к локальным объектам. Вывод сервера считается данными: не вставляй его как HTML/JavaScript. Не разрешай терминальным escape-последовательностям бесконтрольно читать или заменять системный буфер обмена. Сетевые ресурсы для отрисовки терминала не нужны.

### 8. Файловый менеджер: навигация и отображение

Построй полноценный интерфейс файловых операций по модели Проводника Windows 11. Базовые действия должны одинаково работать через панель, контекстное меню, клавиатуру и перетаскивание.

**Навигация**

- Дерево слева загружается по требованию. Стрелка раскрывает узел, нажатие на название открывает каталог справа. Различай загрузку, отсутствие подпапок и отказ в доступе. Ссылочные циклы не должны приводить к бесконечному обходу.
- Двойной щелчок по папке в содержимом открывает её; одиночный выделяет. Дерево и адресная строка синхронизируются с успешным переходом.
- Путь представлен кликабельными сегментами. Щелчок по свободной части, Ctrl+L или Alt+D переводит его в редактируемый текст. Enter выполняет переход, Escape возвращает прежний путь.
- Поддержи абсолютные POSIX-пути и `~` текущего пользователя. Не выполняй произвольную shell-подстановку в адресной строке. Ошибочный путь не уничтожает текущий контекст.
- «Назад», «Вперёд», «Вверх», кнопки мыши для истории, обновление и переход домой работают независимо для каждой сессии. При возврате восстанавливаются прокрутка и выделение, если элементы сохранились.
- F5 действительно перечитывает сервер. После собственных операций актуализируй затронутые каталоги и дерево. Автообновление, если включено, выполняется ограниченным опросом видимой папки.
- Реализуй закрепление и открепление каталогов быстрого доступа для конкретного сервера.
- Поиск по именам в текущем каталоге обязателен. Рекурсивный поиск запускается явно, имеет указанную область, отмену и ограничения нагрузки; нельзя автоматически сканировать весь сервер.

**Представление**

Реализуй восемь режимов из референса: огромные, крупные, обычные и мелкие значки; список; таблица; плитка; содержимое. У режимов должны различаться реальная компоновка и состав информации. «Область сведений», «Область просмотра», показ скрытых файлов и расширений — работающие переключатели.

В таблице обязательны имя, дата изменения, тип и размер. Дополнительные колонки: права, владелец и группа. Поддержи изменение ширины, порядка и видимости колонок, сортировку по колонке, направление сортировки и сохранение настроек.

Доступны сортировка папок перед файлами и понятный порядок имён с числами. Идентичность POSIX-имён остаётся чувствительной к регистру.

Строка состояния показывает число элементов, выделение и размер выбранных обычных файлов. Рекурсивный размер каталога рассчитывается только по запросу с возможностью отмены; не показывай размер directory entry как объём его содержимого. Метаданные и время должны быть подписаны и отображаться последовательно; не придумывай дату создания, если сервер её не предоставляет.

Поддержи одиночное и множественное выделение, Ctrl/Shift, Ctrl+A, клавиатурную навигацию, выделение рамкой в подходящих режимах и сохранение выбора при обновлении. В больших каталогах используй виртуализацию, пакетное обновление и отмену устаревших запросов.

**Контекстные действия и клавиатура**

Меню файла, папки, пустого места и узла дерева соответствуют контексту. Предусмотри открытие, открытие каталога в новой серверной вкладке, загрузку и скачивание, вырезать/копировать/вставить, переименовать, удалить, создать папку/файл, копировать путь, свойства, закрепить и открыть в терминале. Новая вкладка каталога получает имя сервера и собственную сессию.

Горячие клавиши: Ctrl+C/X/V/A, F2, F5, Delete, Ctrl+Shift+N, Alt+Enter, Alt+Left/Right, Alt+Up, Ctrl+L, Ctrl+F, Enter, Escape, Shift+F10.

Ctrl+Tab переключает вкладки, Ctrl+F4 закрывает серверную сессию; дополнительный Ctrl+W не должен отнимать комбинацию у активного терминала. Учитывай контекст фокуса и отображай сочетания в меню.

Состояния «пустая папка», «загрузка», «ошибка», «нет доступа» и «связь потеряна» различаются. Недоступная операция имеет понятную причину. Кнопки не должны исчезать случайно при каждой перезагрузке списка.

### 9. Файловые операции, буфер обмена и передачи

Обязательны создание файлов и каталогов, переименование, удаление, копирование, перемещение, загрузка и скачивание файлов и деревьев каталогов. Обычные операции выполняются через SFTP API, без разбора `ls` и склейки shell-команд из пользовательских имён.

SFTP не гарантирует универсальную серверную операцию копирования. Предпочитай согласованные расширения сервера, затем безопасный существующий `cp` через SSH exec, если доступен, либо потоковое копирование через клиент. Выбор реализации не должен менять смысл операции.

Для shell-команд централизованно обрабатывай POSIX-аргументы, опции, кавычки и exit status. Пути с пробелами, кавычками, переводами строк, начальным дефисом, `$` и `;` не должны превращаться в команды.

Буфер копирования хранит сервер, путь, вид объекта и действие; адресная строка и команды «копировать путь» работают с обычным текстом. Вырезанные элементы визуально отличаются от обычных.

Поддержи копирование файлов через системный буфер между Windows Explorer и приложением в обоих направлениях, используя реальные файловые объекты или отложенную выдачу содержимого.

Для перемещения между файловыми системами или разными серверами сначала заверши и проверь копирование, затем удаляй источник. Межсерверную передачу можно направлять через клиент, без новых связей между серверами. Сбой копирования оставляет исходник на месте.

При совпадении имён предложи заменить, пропустить или сохранить оба с понятными именами; поддержи применение решения к остальным конфликтам. Покажи размеры и время, если известны. Папки объединяются без предварительного удаления существующего дерева. Различай конфликт файл/папка и случай копирования в самого себя либо в собственного потомка.

Удаление требует ясного подтверждения с количеством, путём и сервером. По умолчанию это окончательное удаление на Linux. Не называй его переносом в корзину. Удаление ссылки удаляет ссылку, рекурсивное удаление не следует через symlink к чужому дереву. Корень доступной файловой системы не должен становиться допустимой целью команды удаления из GUI.

Реализуй ограниченный журнал отмены для переименований и перемещений без перезаписи, где обратное действие действительно безопасно. Перед Ctrl+Z проверяй актуальность объектов и отсутствие конфликта; при изменении файлов извне объясняй невозможность отмены. Окончательное удаление и перезапись не объявляются восстанавливаемыми. Отмена выполняющейся передачи и отмена завершённой файловой операции — разные действия.

**Drag-and-drop**

- Из Windows Explorer в открытую папку, строку папки или узел дерева — загрузка; для дерева работают подсветка цели, прокрутка и раскрытие при удержании.
- Внутри одного серверного файлового менеджера — перемещение по умолчанию; Ctrl переключает на копирование. Возле курсора видно фактическое действие и цель.
- Между серверными вкладками — копирование по умолчанию; перенос не должен неожиданно удалять источник.
- Из приложения в Windows Explorer — реальное скачивание через поддерживаемый механизм Windows drag-and-drop, включая отложенную выдачу содержимого виртуальных файлов либо корректно подготовленные локальные файлы. Текст с удалённым путём не является реализацией этого требования.
- Перенос между локальным компьютером и сервером по умолчанию копирует. Удаление локального оригинала после загрузки или удалённого оригинала после скачивания не происходит неожиданно.

Нативный drag-and-drop проверь рано на реальной Windows: поддержка виртуальных файлов, COM/STA при необходимости, ожидание данных, отмена, большой файл и недоступный сервер. Если выбранная библиотека не предоставляет нужный API, реализуй отдельный Windows-адаптер. Не объявляй перенос готовым только по работе внутри приложения.

**Надёжность передач**

Предусмотри общую очередь передач с привязкой к серверным сессиям: название, источник/назначение, реальные байты, скорость, прогресс, оставшееся время при возможности расчёта, отмена и повтор. Пока общий объём неизвестен, показывай соответствующий статус. Ограничь параллелизм и потребление памяти.

Загружай обычный файл во временное имя рядом с назначением, затем выполняй финальное переименование после успешной передачи. Проверяй возможности атомарной замены, перезаписи, сохранения прав и flush; не обещай их без поддержки.

Существующий корректный файл не должен уничтожаться в начале передачи. Отмена и обрыв оставляют явно распознаваемую частичную операцию. Удаляй только собственные временные файлы.

Возобновление допустимо после проверки соответствия источника и частичной копии; при неопределённости предложи начать заново. Повторное соединение не означает разрешение повторить удаление или перезапись. При частичном успехе перечисляй выполненное и невыполненное, а не показывай общее «Готово».

При скачивании учитывай имена Linux, недопустимые в Windows: зарезервированные имена, запрещённые символы, завершающие точки/пробелы и коллизии регистра. Предлагай понятное разрешение конфликта, сохраняй соответствие исходному имени и не допускай выхода из выбранной локальной папки.

### 10. Свойства, права и различия Linux

Окно свойств показывает путь, тип, размер обычного файла, доступные временные отметки, владельца, группу, POSIX-права и цель символической ссылки.

Реализуй изменение rwx/числовых прав и владельца/группы там, где сервер и учётная запись это позволяют. Рекурсивные изменения запускаются отдельным действием. Данные, которые получить нельзя, обозначаются недоступными.

Ссылки различаются визуально; переход по ссылке, копирование самой ссылки и работа с целью имеют определённое поведение. Обрабатывай битые ссылки, циклы, изменение объекта другим процессом и исчезновение каталога. Сокеты, устройства и FIFO не открываются как обычные файлы для скачивания или превью.

Используй POSIX-модель удалённых путей. Windows Path API не должен менять разделители и семантику удалённых имён. Поддержи UTF-8; для имён, которые невозможно без потерь представить в выбранной библиотеке, выдавай явное ограничение и не выполняй разрушительные операции по искажённому имени.

При недостаточных правах покажи ошибку и доступные действия. Повышение прав внутри терминального `sudo` не повышает права SFTP-соединения. Не скрывай это и не устанавливай sudo-helper. Пользователь может подключиться разрешённой на сервере привилегированной учётной записью либо выполнить явную команду в терминале.

Под «полным функционалом Проводника» понимаются перечисленные файловые сценарии и взаимодействия. Специфические для Windows интеграции вроде меню «Пуск», OneDrive, Windows ACL, COM-расширений WinRAR и системной корзины не переносятся на Linux фиктивными кнопками.

Реализуй все применимые пункты; ограничения платформы зафиксируй отдельно. Наличие ограничения у Windows-специфичной функции не оправдывает отсутствие переименования, истории, видов или drag-and-drop.

### 11. Превью и просмотр изображений

**Превью обязательно:** SFTP позволяет получить байты файла, а декодирование и построение миниатюры выполняются на клиенте. Установка ImageMagick или других компонентов на сервер не нужна.

Поддержи как минимум PNG и JPEG; остальные форматы добавляй при наличии комплектного безопасного декодера и проверки.

Нужны миниатюры в соответствующих режимах, область предпросмотра, увеличение, вписывание в окно, масштаб 100%, переход к следующему изображению и скачивание. Просмотр не должен изменять удалённый файл.

Миниатюры создаются лениво для видимых элементов с небольшой очередью. Обычному изображению может потребоваться полное скачивание для декодирования; учитывай этот сетевой расход. Установи настраиваемые лимиты размера файла, числа пикселей, параллельных запросов и локального кэша. Для слишком большого файла предложи отдельное открытие или скачивание.

Ключ кэша учитывает идентичность сервера, пользователя, путь, размер и время изменения; предусмотрена очистка и принудительное обновление. Используй пользовательскую локальную папку с ограниченным доступом. HTML и SVG нельзя отображать как произвольный активный веб-контент. Отсутствие поддержки конкретного формата не должно ломать список файлов.

Небольшие текстовые файлы можно показывать в ограниченном по размеру предпросмотре. Для неподдерживаемого типа предложи скачивание либо явное открытие временной локальной копии подходящим приложением. Изменения локальной копии автоматически обратно не загружаются.

Полноценный редактор конфигураций и редактирование изображений — дополнительные возможности после выполнения обязательного объёма. Удалённые исполняемые файлы не запускаются локально обычным просмотром.

### 12. Графический диспетчер задач

Отдельный пункт серверной навигации открывает графический раздел в стилистике приложенного Диспетчера задач Windows 11. Основные представления — «Процессы» и «Производительность». Сохрани общую навигацию серверной вкладки и читаемую плотность таблицы.

**«Процессы»:** имя, PID, пользователь, состояние, CPU, память; при доступности — командная строка и дисковый ввод-вывод. Нужны сортировка, поиск по имени/PID/пользователю, сохранение выделения и аккуратная тепловая подсветка числовых ячеек.

Полную командную строку показывай осмысленно, не сохраняя её автоматически в журнал: она может содержать секреты.

**«Производительность»:** реальная загрузка CPU, память и swap, uptime, load average, сетевые скорости по интерфейсам, дисковый ввод-вывод и доступное место там, где эти данные доступны. Графики хранят ограниченную историю. Наблюдаемую область — хост, контейнер или доступное пространство имён — не называй автоматически всем физическим сервером.

Получай данные из `/proc/stat`, `/proc/meminfo`, `/proc/uptime`, `/proc/loadavg`, `/proc/net/dev`, `/proc/diskstats` и доступных `/proc/<pid>/stat`, `status`, `cmdline`, `io`. Допустимы существующие `ps`, `df` и другие штатные утилиты после проверки возможностей. Не считывай весь `/proc` рекурсивно. Не запускай отдельный SSH-процесс на каждый показатель каждого PID.

Используй ограниченные пакетные SSH exec-запросы без PTY либо подходящее чтение SFTP. Формат результатов должен корректно обрабатывать пробелы, скобки, переносы строк и NUL в соответствующих полях. Нулевой размер псевдофайла `/proc` не означает отсутствие содержимого. Отсутствие утилиты или разрешения приводит к точному ограничению, а не к установке пакета.

CPU и скорости вычисляй по разнице счётчиков и времени между замерами. Определи и подпиши шкалу CPU процесса: доля всей машины 0–100% либо модель 100% на ядро; не смешивай их. Учти число CPU, единицы памяти, clock ticks, переполнение/сброс счётчиков и исчезновение процессов. Использование памяти рассчитывай с учётом `MemAvailable`, когда оно доступно.

Сетевая статистика интерфейсов не является сетевой статистикой конкретного процесса. Нельзя выдавать `/proc/<pid>/net/dev` за персональный трафик PID. Неизмеримые показатели показывай как «Недоступно» с причиной; 0 допустим только как реальное измеренное значение.

По умолчанию обновляй активный экран примерно раз в 2 секунды; интервал настраивается. В фоне опрос замедляется или приостанавливается, после закрытия сессии прекращается. Новый опрос не накапливается поверх незавершённого. Показывай время последнего успешного замера и состояние устаревших данных.

«Завершить процесс» отправляет SIGTERM после подтверждения. SIGKILL — отдельное явно обозначенное действие. Перед сигналом повторно проверь PID, start time и владельца; если процесс сменился, откажись от действия. Учитывай остаточную гонку PID, не заявляй атомарную гарантию без соответствующего механизма. Права и отказ сервера отображаются корректно; автоматического `sudo` нет.

Дополнительно предусмотрен запуск установленного `htop` в терминале. При его отсутствии предложи существующий `top`; при отсутствии обоих графический монитор продолжает работать в пределах доступных данных. Текстовый `htop` не заменяет графическую реализацию, а его ANSI-вывод не служит источником таблицы.

### 13. Настройки, ошибки и эксплуатация

Сохраняй профили, доверенные ключи, закладки, ширину дерева, режимы просмотра, колонки, тему, настройки терминала и интервалы опроса. Используй версионирование схемы и безопасную запись настроек. Восстановление ранее открытых вкладок не должно незаметно выполнять удалённые команды.

Сообщения об ошибках различают DNS, timeout, отказ аутентификации, смену ключа, недоступный SFTP, отсутствие прав, переполнение диска и потерю связи. Пользователь видит затронутый сервер, путь или операцию. Технические детали можно раскрыть отдельно.

Диагностический журнал локальный, ограничен по размеру и исключает секреты и полное содержимое терминала по умолчанию. В интерфейсе нет телеметрии или внешней синхронизации, необходимых для работы.

Сначала обеспечь обязательные сценарии. Jump hosts, проброс портов, архивы, менеджер systemd, синхронизация каталогов, редактирование текстов и дополнительные платформы можно развивать после этого; не расширяй ими проект ценой незавершённого файлового менеджера.

### 14. Проверка и критерии приёмки

Проверяй реальную Release-сборку, доступный локальный SSH-стенд и Windows UI. Подготовка изолированного тестового стенда относится к разработке; само приложение не должно разворачивать его на управляемом сервере. Не используй чужие или старые учётные данные. Тестовые файлы создавай только в предназначенных для испытаний каталогах.

Матрица обязательных проверок:

1. **Сохранение серверов.** Добавлены два сервера; после перезапуска сохранены имена, настройки и подтверждённые ключи. Секреты отсутствуют в открытом виде в конфигурации.
2. **Доверие SSH.** Первый host key требует решения. Отмена не допускает вход. Изменённый ключ блокирует терминал, SFTP и фоновые соединения. Изменение адреса профиля не наследует доверие к другому endpoint.
3. **Независимость сессий.** Несколько вкладок, включая две сессии одного сервера, сохраняют независимые пути и терминалы. Закрытие одной не разрывает остальные. После её закрытия не остаётся опроса, соединений и обработчиков.
4. **Терминал.** Выполняет интерактивную программу, корректно обрабатывает кириллицу, Ctrl+C, вставку и resize. Переключение на файлы и обратно не сбрасывает shell.
5. **Навигация.** Дерево, двойной щелчок, ввод пути, сегменты адреса, история, переход вверх и F5 приводят к согласованному содержимому. Быстрые переходы не показывают запоздалые результаты другой папки.
6. **Представления.** Проверены все восемь режимов, колонки, сортировка, скрытые файлы, расширения, поиск, множественное выделение и горячие клавиши. Размеры папок не выдуманы.
7. **Файловые операции.** Создание, переименование, копирование, перемещение, удаление и свойства проверены на реальных объектах. Действия через меню, клавиатуру и панель дают одинаковый результат. Проверены безопасная отмена переименования и отказ от отмены при внешнем изменении объекта.
8. **Обмен с Windows.** Файлы и папки переносятся из Windows Explorer в список и дерево приложения, обратно в Explorer и между серверными вкладками. Проверен системный буфер файлов. Цель и copy/move отображаются правильно. Исходники не исчезают при неудачной передаче.
9. **Сбои передач.** Протестированы конфликты имён, существующие вложенные папки, файл вместо папки, перенос через разные файловые системы, обрыв сети, отмена и недостаток места. Повтор не уничтожает корректный оригинал.
10. **Особенности имён и ссылок.** Имена с кириллицей, пробелами, одинарной кавычкой, начальным дефисом, `;` и `$` не повреждаются и не исполняются. Проверены symlink, битая ссылка, ссылка-цикл, недоступная папка и несовместимое с Windows имя.
11. **Изображения.** Миниатюры и просмотр PNG/JPEG работают без программ обработки изображений на сервере. Повреждённое, изменённое и слишком большое изображение не блокируют интерфейс.
12. **Мониторинг.** Графический монитор работает на сервере без `htop` и Python. Реальные CPU/память сравниваются с независимым измерением на том же сервере с учётом времени и формулы. Недоступные показатели не превращаются в нули; выбранный PID не подменяется новым процессом.
13. **Ограниченный доступ.** Проверены обычная учётная запись, ограниченные права, SFTP без shell и shell без SFTP. Доступные разделы работают, ограничения объясняются, серверная конфигурация не меняется.
14. **Нагрузка.** Испытаны каталог хотя бы с 10 000 элементов и потоковая передача файла больше 2 ГБ. Интерфейс остаётся отзывчивым, память не растёт пропорционально всему файлу. Отдельно проверь искусственную задержку сети и быстрое закрытие вкладки.
15. **Визуальная проверка.** Проверены несколько размеров окна и масштабы 100/125/150/200%, светлая и тёмная темы, контекстные меню, фокус, клавиатура и области drag-and-drop. Сними реальные экраны и исправь заметные отличия от референсов.
16. **Самостоятельная поставка.** На чистой Windows 11 без инструментов разработки и отдельно установленных runtime запускается комплектный EXE, открывается терминал и работает drag-and-drop. Для запуска не требуется доступ к интернету; для работы с сервером нужен только доступ к его SSH.
17. **Отсутствие установки на сервер.** После сеанса на управляемом сервере не появилось установленных компонентов, служб или изменений системной конфигурации. Остались только явно созданные пользователем данные и корректно обработанные временные файлы передач.

Пиши автоматические тесты там, где они проверяют существенный риск: доверие ключам, POSIX-пути и quoting, разбор метрик, конфликты/отмена передач, гонки навигации и освобождение сессий. UI и интеграцию дополняй реальными сценариями. Не подменяй сетевые и Windows-проверки исключительно моками.

### 15. Сборка, документация и завершение

Предоставь решение проекта, зафиксированные версии зависимостей, скрипт Release-сборки для Windows и самостоятельный комплект с EXE.

Для C# настрой self-contained одновременно для .NET и Windows App SDK; проверь также зависимости терминала и нативных библиотек. Предпочтительный результат — portable ZIP с EXE и всем необходимым; установщик EXE можно добавить как удобный способ доставки.

Не заявляй single-file или отсутствие внешних зависимостей без фактического испытания. Если поставляется WebView2 Fixed Version, он входит в комплект и обнаруживается по правильному пути. Все ресурсы, иконки, шрифты и терминальные скрипты доступны локально. Отдельно зафиксируй минимальную проверенную версию Windows, архитектуру и механизм обновления комплектных runtime.

README объясняет запуск, сборку, добавление сервера, доверие ключам, особенности окончательного удаления, права Linux, ограничения SFTP и местонахождение настроек. Добавь лицензии распространяемых компонентов. Если сертификата подписи нет, явно сообщи статус неподписанной сборки, не обходи проверки Windows и не обещай отсутствие предупреждений.

Развивай приложение этапами:

1. Проверка стека и упаковки.
2. Доверенное подключение и вкладки.
3. Терминал и файловая навигация.
4. Полный набор файловых операций и передач.
5. Превью и мониторинг.
6. Визуальная доводка и испытания.

Каждый этап заканчивается работающим интегрированным состоянием. Первый вертикальный срез не является финальной версией.

В конце передай краткий отчёт: что реализовано, где EXE и исходники, как запустить, какие испытания действительно выполнены, какие ограничения подтверждены и что осталось непроверенным. Соотнеси результат с `ACCEPTANCE.md`. Отсутствующие обязательные функции обозначай как незавершённые, а не как особенности реализации.
