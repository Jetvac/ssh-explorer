# Профили и парольный вход beta.2

`Сохранить` и `Сохранить и подключиться` имеют отдельные результаты. При подключении точное содержимое общего поля пароля передаётся в памяти. Пробелы, кавычки, Unicode и пустая парольная фраза ключа не обрезаются. Временное отображение пароля меняет только представление поля. Неотредактированное пустое поле обычного пароля означает, что нужен стандартный запрос учётных данных.

Если пользователь включил сохранение, `Сохранить и подключиться` сначала записывает профиль без нового секрета. После успешного подключения вызывается `SaveAuthenticatedSecretAsync`. Метод проверяет, что профиль существует, сохранение ещё включено, адрес, порт, имя пользователя, способ входа и путь ключа соответствуют успешной попытке. Поздний ответ от удалённого или изменённого профиля не записывает секрет. При отказе атомарной записи прежняя защищённая копия остаётся действующей. Отдельное `Сохранить` явно сообщает, что запись введённого секрета происходит без сетевой проверки.

`ProfileSubmission` не включает секрет в `ToString()`. Диагностика сохранения пишет GUID редактора, этап, результат и очищенные сведения об исключении; пароль и поля профиля в неё не включаются. Настройки показывают версию и commit сборки. Кнопка копирования диагностики копирует только путь к каталогу журналов.

Запросы Credentials, Trust и Interactive принимают владельца и токен отмены. Общий `ModalRunner` закрывает показанный запрос при отмене с другого потока и закрытии владельца. Уже отменённый запрос не создаёт окно. Сериализация и проверка актуальности очереди конкретной попытки принадлежат `ConnectionInteraction`; этот компонент не создаёт собственную очередь диалогов.

## Подтверждённые проверки

На рабочем компьютере выполнены Release build с **0 warnings / 0 errors** и **85/85** проверок `--no-windows`; [лог](test-results/beta2-profiles-headless.log). Не вызывались `Show`/`ShowDialog`, CUA или физический ввод. В набор входят реальные Windows DPAPI, реальные ошибки доступа и sharing violation в изолированном каталоге, транзакции секрета после входа, сохранение прежнего корректного секрета, пустая passphrase, безопасное чтение клона schema1, настоящие непоказанные WPF-контролы и обработчики изменения текста. Искусственно вызванный Loaded в проверке позднего чтения — компонентная проверка порядка обработки, не доказательство живого окна.

Клон beta.1 создаётся из отдельного schema1 fixture store в `.tools`, включая настройки, доверенный ключ и DPAPI reference. Исходные fixture bytes остаются неизменными. Это проверка совместимости формата; пользовательское хранилище не читается и не меняется.

Дополнительно выполнен `--no-windows --baseline-core <опубликованный-beta.1>/SSHExplorer.Core.dll`: **92/92 PASS**, включая прежние 85 и 7 проверок опубликованной библиотеки; [лог](test-results/beta2-profiles-published-baseline.log). Это не отдельные 92 пользовательских маршрута. В отдельный collectible AssemblyLoadContext загружен точный Core из опубликованного portable beta.1:

* InformationalVersion: `0.2.0-beta.1+eda137a734e8fc259eb97fca300b2072d11232a8`.
* SHA256 Core: `d9da19f09a2a6277930fc9d3c46aa6b4444393a83b40331c971b16a298693fca`.

Старые реальные API `SaveProfileAsync`, `SaveAsync` и `HostTrustStore.VerifyAsync` создали отдельный fixture store, включая DPAPI secret reference, настройки, bookmark и сохранённый host key. Загрузчик не загружал старый App, не создавал его окна и не запускал старый EXE. Beta.2 прочитала копию store, отредактировала профиль и повторно прочитала его с теми же ID и секретом. Подтверждены неизменные SHA256 исходных fixture файлов и всех DLL рядом с опубликованным Core. Старые опубликованные файлы не перезаписывались. Этот дополнительный тест необязателен в CI, поскольку baseline DLL не входит в репозиторий.

Дополнительно закрыт обнаруженный при анализе путь: удаление файла сохранённого секрета после открытия формы раньше могло вывести ожидаемую `InvalidOperationException` из асинхронного обработчика. Теперь ошибка показывается внутри формы, ввод сохраняется и повторное сохранение с новым значением возможно. Это отдельная регрессия с тестом, **не установленная причина пользовательского сообщения о падении**.

## Подготовленные сценарии CI

Полный STA набор допускает окна только при `CI=true`. На хосте следует использовать исключительно `--no-windows`. В CI дополнительные проверки вызывают настоящие Credentials/Trust/Interactive/Profile диалоги, отменяют их с worker-потока, проверяют владельца, закрытие владельца и отсутствие оставшихся окон. Эти новые проверки на хосте не запускались.

Обычный сетевой маршрут использует общий `scripts/testing/auth_fixture.py`, а не внедрённые `suppliedCredentials` или `trustOverride`. Изолированный fixture генерирует собственный ключ и независимо вычисленный отпечаток, точный пароль с Unicode и пробелами, реальный SFTP каталог `README.txt` и пустую папку. CI меняет свойства настоящих контролов WPF и вызывает настоящие события кнопок:

1. MainWindow «Добавить сервер» → ProfileDialog PasswordBox → «Сохранить и подключиться».
2. Настоящий TrustDialog сравнивается с независимо записанным отпечатком fixture; кнопка доверия сохраняет ключ.
3. Проверяется отсутствие записи секрета до входа, Connected, фактическая навигация SFTP и README в таблице.
4. После записи DPAPI запускается новый процесс **тестового STA runner**. Он открывает тот же изолированный store и нажимает обычную кнопку «Подключиться», проверяя вход без нового Credentials/Trust окна.

```powershell
# Только непоказанные проверки на рабочем хосте.
.tools/profile-beta2/SSHExplorer.ProfileTests.exe --no-windows
# Дополнительная Core-only совместимость с точной опубликованной beta.1.
.tools/profile-beta2/SSHExplorer.ProfileTests.exe --no-windows --baseline-core <published-beta.1>/SSHExplorer.Core.dll
# Только в CI после запуска общего headless fixture.
SSHExplorer.ProfileTests.exe --ordinary-only --ordinary-fixture <ignored-fixture-directory>/fixture.json
```

Результат нового modal/network CI на момент написания этого документа ожидается. Тестовый STA процесс не равнозначен опубликованному EXE; присваивание свойств контролам не равно физическому вводу. Живой ввод пользователя, проверка опубликованной поставки и матрица DPI/High Contrast отложены по указанию пользователя. Падение актуальной beta.1 при парольном входе пока не воспроизведено; новый код не объявляется доказательством устранения неизвестного падения.
