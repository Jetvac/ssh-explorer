## 1. Экспорт и импорт

- Формат `.sshx` — JSON с версией формата. Неизвестный, повреждённый или более новый файл отклоняется с объяснением.
- Пароли под защитой Windows (DPAPI) открываются только той же учётной записью, поэтому по умолчанию **не переносятся**: файл можно передавать. По выбору пароли и секреты Docker шифруются парольной фразой (PBKDF2-SHA256, 600 000 итераций → AES-256-GCM) и при импорте сохраняются под DPAPI этого компьютера. Ключевые файлы не переносятся — только путь.
- Импорт показывает каждый сервер и действие: импортировать, пропустить, заменить существующий (сохраняя его пароль) или добавить копию. Совпадения по адресу или имени по умолчанию пропускаются.
- Безопасность импорта: автоматические скрипты приходят приостановленными, туннели, открытые для других компьютеров, не открываются при подключении сами. Доверенный ключ из файла никогда не заменяет другой уже доверенный ключ.

## 2. Наборы правил файервола

- «Файервол» → «Наборы правил…»: сохранить правила сервера как набор (с политикой входящих или без), переименовать, удалить. Правила, которые набор описать не может (пересылка, профили приложений, порт источника, адрес назначения), называются при сохранении.
- Применение добавляет только недостающие правила в порядке набора; одинаковые правила с другим комментарием не дублируются. По выбору сервер становится точной копией набора: остальные правила удаляются.
- Перед применением видны команды и доступ вашего SSH-подключения; правила для отдельных адресов отмечаются. Применение идёт через безопасное применение с проверкой нового подключения и возвратом.

## 3–4. Раздел «Защита SSH»

- Новый раздел левой панели (после «Файервола»). Показывает, как входит этот профиль, и ключи из `~/.ssh/authorized_keys` пользователя: тип, отпечаток, комментарий, ограничения; слабые ключи и ключ текущего входа отмечены. Ключ можно добавить (файл `.pub`) или удалить по точной строке.
- «Вход по ключу…»: ключ Ed25519 создаётся на этом компьютере в `%USERPROFILE%\.ssh` (парольная фраза — через `ssh-keygen` Windows), на сервер отправляется только открытый ключ с нужными правами `~/.ssh`. Новое подключение проверяет вход по ключу (принимая только уже проверенный ключ сервера), и только после этого профиль переключается.
- Настройки SSH-сервера: действующие значения `sshd -T` для этого пользователя (без root — приблизительно по файлам). Замечания по важности: вход по паролю, root по паролю, пустые пароли, попытки входа, время на вход, X11, стандартный порт, отсутствие AllowUsers. Исправление, которое отрезало бы доступ этому профилю (пароли при входе по паролю), заблокировано с объяснением.
- Исправления пишутся в `/etc/ssh/sshd_config.d/00-sshexplorer.conf` (читается первым и поэтому главнее, в том числе `50-cloud-init.conf`), а без Include — в отмеченный блок в начале `sshd_config`. Безопасное применение: сохранение, таймер возврата, `sshd -t`, перезагрузка без обрыва сеансов, проверка новым подключением, иначе возврат.

## 5. Выполнение на нескольких серверах

- «Главная» → «Выполнить на нескольких…» (или правый щелчок по серверу → «Выполнить на группе…»): свои команды или сохранённый скрипт, выбор серверов (отмечена группа выбранного сервера), 1–8 одновременно, таймаут на сервер, остановка на первой ошибке.
- Каждый сервер — отдельное новое подключение с сохранёнными данными входа; без сохранённого пароля сервер пропускается, неподтверждённый ключ сервера не принимается (сервер нужно один раз открыть во вкладке). Текст скрипта передаётся файлом, как в «Скриптах».
- Таблица: состояние, код, время, итог; вывод выбранного сервера; «Повторить на неудачных»; «Остановить».

## 6. Копирование на другой сервер

- Копирование из вкладки во вкладку уже было (перетаскивание и Ctrl+C/Ctrl+V). Добавлена явная команда файлового менеджера «Копировать на другой сервер…»: выбор открытой вкладки сервера и папки (подставляется открытая там), копирование или перемещение. Данные идут через этот компьютер — серверы не подключаются друг к другу и не получают ничьих паролей и ключей.

## 7. Задания cron

- Раздел «Задания cron»: crontab пользователя или root (через sudo без пароля), каждое задание словами («По будням в 09:00») и ближайший запуск по времени сервера; переменные окружения и комментарии сохраняются.
- Добавить, изменить, выключить и включить (точно как было), удалить. Редактор: готовые расписания, пять полей с проверкой каждого, описание и три ближайших запуска.
- Перед каждым изменением crontab перечитывается; если его изменили на сервере, запись отменяется. Прежний crontab сохраняется в `~/.cache/sshexplorer`. Новый текст передаётся файлом.

## 8. Обновления пакетов

- «Сервер» → «Обновления…»: что обновит apt или dnf/yum (обновления безопасности первыми), сколько лет спискам пакетов, нужна ли перезагрузка. Без root и без загрузки из сети.
- Установка — только в терминале: кнопка вписывает готовую команду (все обновления, только безопасность, обновить списки), пользователь проверяет её и нажимает Enter; пароль sudo вводится в терминале, приложение его не видит.
