## Обычный маршрут

Выберите один текст и команду «Редактировать в Блокноте». Двойной щелчок открывает текст в выбранном редакторе, изображения — в просмотрщике. Отдельный «Просмотр» сохраняет встроенный read-only просмотр. В параметрах можно выбрать доверенный установленный EXE. Системный Блокнот запускается через `%SystemRoot%/System32/notepad.exe`, отдельный `ProcessStartInfo.ArgumentList`, без shell и без ассоциации самого документа. `.sh`, `.bat`, `.ps1` не выполняются.

Сначала приложение показывает сервер/путь и условия замены. Ctrl+S записывает рабочую копию, после чего SSH Explorer обнаруживает сохранённые байты, создаёт устойчивый snapshot, отправляет и перечитывает результат. Статус «Сохранено на сервере» означает подтверждённый SHA-256 назначения. Несохранённый буфер Блокнота приложению недоступен; завершение стартового процесса не означает сохранение. Процессы внешнего редактора никогда не завершаются клиентом.

Список «Редактируемые документы» показывает сервер, полный путь, состояние, поколение и подтверждённый хеш. Есть открытие редактора, проверка изменений, отправка, повтор/возобновление, экспорт локальной копии, отдельная серверная копия и завершение отслеживания. Известные неотправленные изменения учитываются при закрытии серверной вкладки: дождаться, оставить копии и отключиться либо отменить закрытие. Скрытое SSH-соединение после закрытия не сохраняется.

## Байты и хранение

Рабочая папка `%LOCALAPPDATA%/SSHExplorer/RemoteEdits/<GUID>` хранит точное отображение server identity + исходный/разрешённый путь ↔ безопасное локальное имя. Идентичность включает профиль, endpoint, пользователя и проверенный host key. Имена с POSIX-регистром, reserved Windows names и длинным basename не превращаются в локальные пути. Один открытый canonical target одного сервера использует одну копию.

Рабочие документы и snapshots — приватные локальные данные пользователя, не логи и не зашифрованное хранилище секретов. Они не включаются в Git, CI artifacts или portable ZIP. Завершённые документы сохраняются до отдельной явной очистки; автоматического удаления незавершённых копий нет. Повреждённые журналы оставляются на диске и учитываются отдельным предупреждением.

Клиент не перекодирует документ. Строгий detector учитывает BOM, UTF-16 и printable/control characters; неизвестная legacy encoding требует явного выбора. Формат фиксирует encoding/BOM, смешанные LF/CRLF/CR и финальный перевод строки. Смена encoding/BOM или вида окончаний требует подтверждения конкретного snapshot hash. Лимит — 32 МиБ, обычный 10 МиБ/длинная строка проверяется отдельно; крупные файлы доступны через скачивание/очередь передач. Чтение, hashing и сеть выполняются вне UI; на подготовке/отправке доступна отмена.

Watcher — только сигнал: Changed/Created/Deleted/Renamed/Error объединяются; два стабильных чтения и retries защищают от промежуточной записи/замены. Периодическая сверка и возврат в приложение закрывают пропуск событий. Исчезновение локального файла не удаляет и не обнуляет сервер. Нулевая сохранённая версия допустима. Отправки сериализованы по документу. Журнал и неизменяемые `snapshot.bin`/`operation.bin` переживают аварийный выход.

Внешнее «Сохранить как» в другой путь автоматически не подменяет документ. Выбранную копию можно явно подключить через меню; автоматическая отправка при этом отключается до отдельного подтверждённого действия. При старте восстановленные документы приостановлены. Для возобновления нужно обычное подключение и совпадающий host key/identity; старая правка при старте не отправляется.

## Серверное сохранение и пределы

Транспорт использует только SFTP, без установки и без зависимости от SSH exec. Открывается обычный файл; FIFO/socket/device запрещены. Для ссылки пользователь явно выбирает цель. Исходный link text и canonical target перепроверяются; сама ссылка не заменяется обычным файлом.

Перед записью и непосредственно перед заменой читается серверное содержимое и сравнивается SHA-256, mode и owner/group. Совпадения длины/mtime недостаточно. Собственный sibling temporary создаётся exclusive, до передачи получает mode0600. Проверяется весь загруженный контент, восстанавливаются и проверяются POSIX mode (включая executable), uid/gid в пределах прав пользователя. При невозможности — остановка без замены оригинала. До rename атомарно записывается локальный operation journal с предыдущим/новым hash, поколением и метаданными.

Финализация использует проверенный POSIX rename extension; неподдерживаемая замена останавливается, предлагается отдельная копия. Delete+upload и скрытого backup fallback нет. После commit назначение перечитывается; только затем baseline обновляется. При потере ответа результат UNKNOWN: восстановление сравнивает destination со старым и отправленным hash, третья версия становится конфликтом. Rollback не может затереть актуальный серверный файл.

При конфликте можно получить серверную версию, сохранить свою рядом, продолжить правку или явно заменить проверенный hash. Подтверждение не переносится на новую внешнюю версию. Новый inode может менять ACL/xattr и hardlink semantics: до первого открытия пользователь явно соглашается с таким способом замены либо выбирает отдельную копию. SFTP v3 не даёт общего compare-and-swap по hash: окно гонки стороннего писателя между последней проверкой и rename остаётся. Flush не доказывает физический fsync. Условия прямо показаны в приложении.
