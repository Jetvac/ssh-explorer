Каждый пункт проверяется в CI: Windows-сервер — настоящий OpenSSH Server на Windows-раннере GitHub, окна — UI-проверками.

## 1. Протокол в профиле

- Новое поле профиля «Протокол»: SSH (по умолчанию, существующие профили не меняются) или RDP. Для RDP — порт 3389, домен, пользователь, пароль; поля SSH (ключ, агент, начальная папка) скрыты.
- «Главная»: значок протокола у каждого сервера, двойной щелчок открывает вкладку нужного типа.
- У профиля SSH, определённого как Windows, — «Открыть по RDP» в правом щелчке и на странице «Сервер»: тот же адрес и пользователь, без второго профиля. Профиль RDP можно «Открыть файлы по SSH», если на сервере есть OpenSSH.

## 2. RDP во вкладке

- Элемент ActiveX `mstscax.dll`, который есть в каждой Windows 11 и который использует mRemoteNG; вкладка RDP стоит рядом с вкладками SSH, закрывается так же, переподключается после обрыва.
- Размер рабочего стола подстраивается под вкладку (без переподключения, где сервер это поддерживает), иначе — масштабирование. Полный экран, Ctrl+Alt+Del, «Отправить Win», снимок окна.
- Проверка подлинности на уровне сети (NLA/CredSSP) включена по умолчанию. Буфер обмена — да; диски, принтеры, смарт-карты, звук и микрофон — по выбору в профиле, по умолчанию выключены.
- Сохранённый пароль (DPAPI) передаётся только элементу RDP в этом процессе; не пишется в файлы `.rdp`, журналы и командную строку. «Открыть в mstsc» — временный `.rdp` без пароля.

## 3. Сертификат RDP

- Отпечаток сертификата сервера показывается при первом подключении и сохраняется в `hostkeys.json` рядом с ключами SSH. Изменённый сертификат блокирует вход с объяснением, как сейчас для SSH. Доверенный центром сертификации сертификат с совпадающим именем принимается без вопроса.

## 4. RDP через SSH и шлюз

- В профиле RDP «Подключаться через» — тот же выбор сохранённого сервера SSH или цепочки, что в 0.3. Приложение само открывает локальный туннель на `127.0.0.1:<свободный порт>` → `<сервер>:3389` и закрывает его вместе с вкладкой. Проверка сертификата идёт по имени целевого сервера, не по 127.0.0.1.
- RD Gateway: адрес шлюза, свои или те же учётные данные.

## 5–6. Импорт

- mRemoteNG: подключения RDP больше не пропускаются — переносятся адрес, порт, домен, пользователь, разрешение, перенаправления, шлюз, папки и наследование. VNC, Telnet, HTTP и прочие по-прежнему называются и пропускаются.
- Пароли mRemoteNG — только если вы отметили «Импортировать пароли»: расшифровываются (AES-GCM, PBKDF2) введённым паролем mRemoteNG или стандартным, если свой не задавался. Полностью зашифрованный файл открывается тем же паролем. Расшифрованное сразу сохраняется под DPAPI и нигде не показывается.
- Файлы `.rdp` (один или несколько) и список серверов из `HKCU\Software\Microsoft\Terminal Server Client` — как сейчас импорт PuTTY: предпросмотр, дубликаты не отмечены.

## 7. Наследование из папки

- Группе на «Главной» можно задать пользователя, домен, пароль и параметры RDP; сервер с «Наследовать» берёт их из ближайшей папки. Импорт из mRemoteNG сохраняет наследование, а не копирует значения.

## 8–10. Windows-серверы по SSH (OpenSSH Server)

- ОС определяется при подключении. Для Windows разделы, которых там нет (cron, ufw, настройки `sshd` Linux, Docker при отсутствии), скрыты с объяснением.
- Файлы: корень — список дисков, адресная строка `C:\Users\...`, права — владелец и атрибуты вместо rwx; передачи, редактирование и поиск по имени работают как с Linux.
- Терминал: PowerShell по умолчанию (или оболочка сервера).
- Диспетчер задач, «Сервер», службы и журналы событий — через PowerShell (`Get-CimInstance`, `Get-Service`, `Get-WinEvent`), без установки чего-либо на сервер. Повышение прав: на Windows его нет, как `sudo`, — изменения доступны, если пользователь SSH — администратор; иначе действия недоступны с объяснением.

## 11. Брандмауэр Windows

- Правила `Get-NetFirewallRule` с портами и адресами, включение, добавление и удаление. Безопасное применение по образцу ufw: экспорт политики, запланированная задача возврата через 90 с, проверка новым подключением (SSH или RDP), отмена задачи.

## 12. Остальное

- «Выполнить на нескольких…» — PowerShell на Windows-серверах, вместе с Linux в одной таблице. Оповещения о дисках и остановленных автоматических службах Windows. `.sshx` переносит параметры RDP и наследование.

## Вне 0.5

VNC, Telnet, HTTP-вкладки и WinRM — после 0.5, если понадобятся. Вкладка RDP в CI проверяется на настоящем RDP-сервере раннера, если GitHub это позволяет; иначе — подключение и сертификат проверяются на тестовых данных, а сам рабочий стол — вашей приёмкой.
