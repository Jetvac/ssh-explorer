# Реализация и проверка Windows UI

В beta.2 добавлены independent DataGridCell template без внутренних focus borders, fixed status message, полноширинные tree headers/current-folder marker, замороженные заполненные vector ImageSource иконки, anchored flyout и явные command glyphs. Все восемь видов наследуют общий item state. Монитор и очередь передач обновляют существующие строки, drop feedback очищается при завершении/уходе/Esc/закрытии. Общая реализация переходов — [MOTION_SPEC](MOTION_SPEC.md), матрица — [UI_PARITY](UI_PARITY.md). Живые screenshots ниже исторические; прежняя ошибка побочного запуска desktop в профильных тестах и её исправление описаны в [PROFILE_FLOW_BETA2](PROFILE_FLOW_BETA2.md).

Дата: 03.11.2026. Все экраны используют реальные данные из изолированного Linux SSH/SFTP-стенда; показанные пути и процессы не являются демонстрационными записями приложения.

## Компоненты

- `MainWindow`, `SessionView` и их реально используемые `HomeViewModel`/`SessionViewModel`: закреплённая Главная, поиск/сортировка профилей, CRUD, независимые вкладки, перестановка, общий сайдбар 244 DIP с сохраняемой шириной, состояния сессии. Переподключение заменяет сессию в той же вкладке; переносит путь, файловую историю, выбор, прокрутку и вид. Все дополнительные терминальные окна закрываются с серверной сессией.
- `Dialogs`: пароль/passphrase и keyboard-interactive, первое доверие host key (постоянное/сессионное/отмена), отдельное удаление сохранённого доверия, настройки. Секреты вводятся в PasswordBox. Функция хранения делегирована DPAPI Core.
- `FileBrowserView`: кликабельные сегменты пути и редактирование, домашняя папка/корень/закладки/ленивое дерево, история и поколение запросов, локальный поиск и отдельный ограниченный рекурсивный поиск (500 папок, 10 000 совпадений, 60 секунд, отмена). CRUD, копирование/вырезание/вставка, загрузка/скачивание, свойства/права/UID/GID и явное вычисление размера дерева. Контекстное меню пустого места, объекта и дерева различается. Файловые клавиши не маршрутизируются в активный терминал.
- Восемь видов: огромные/крупные/обычные/мелкие значки, вертикальный список, виртуализированная таблица, плитка и расширенные вертикальные строки «Содержимое». Табличные колонки изменяют ширину/порядок/видимость и сохраняются. Числа в именах сортируются естественно; папки первыми. Дата создания не выдумывается, неизвестные метаданные отмечаются.
- `VirtualizingWrapPanel`: переработка контейнеров только видимых рядов значков. Список и Содержимое используют штатный VirtualizingStackPanel, таблица — штатный DataGrid.
- Клиентский PNG/JPEG: ленивая загрузка, лимиты байтов/пикселей/очереди/кэша, metadata key, отмена миниатюр старой папки, F5 очищает кэш. Просмотр: вписать/100%/zoom/next/previous/скачать; поколение и отмена предотвращают запоздалый старый кадр. Повреждённое изображение не выполняет активный контент и не ломает файловый список.
- Windows FileDrop: локальные файлы/папки загружаются в папку, строку каталога или узел дерева. Исходящие файлы сначала скачиваются в собственный TransferCache, затем передаются настоящим FileDrop; при отпускании мыши раньше готовности подготовленные файлы помещаются в системный буфер. Обычные файлы кэшируются по пути/размеру/mtime для повторного перетаскивания; каталоги подготавливаются заново. Настройки содержат явную очистку локальных копий. Это подготовленные локальные объекты, а не deferred virtual files.
- Внутренний файловый буфер передаёт через OLE только сырой непрозрачный токен MemoryStream. Ограниченный 64 записями локальный реестр хранит WeakReference на владельца сессии и очищается при закрытии; никакой сериализации или десериализации живой SSH-сессии/BinaryFormatter нет. Если токен недоступен другому процессу, используется настоящий FileDrop.
- `TransfersWindow`: состояние, источник/назначение, реальные байты/скорость/процент/ETA, результат, отмена и повтор. Решение конфликтов можно применить к аналогичным конфликтам текущей попытки; retry заново требует решения.
- `MonitorView`: реальные процессы с поиском/сортировкой/тепловой подсветкой, nullable-показатели с причиной, два графика и сеть/диск/место, последнее успешное время, явные подтверждения SIGTERM/SIGKILL. Опрос только активного раздела активной вкладки, без накопления запросов. htop/top запускается в отдельном PTY-контексте.
- Light/Dark/System/HighContrast задаются DynamicResource и системными цветами. Окно использует штатную рамку, Snap и PerMonitorV2 DPI. Экспериментальный WPF ThemeMode API не используется.

## MVVM: фактическое разделение состояния

Все четыре экрана имеют `DataContext` и отдельные производные `ObservableObject` с `INotifyPropertyChanged`. Это используемое состояние экранов, а не вспомогательные неиспользуемые DTO.

| ViewModel | Вынесенное состояние и поведение | Реальная связь с представлением |
|---|---|---|
| `HomeViewModel` | Сохранённые профили, активные состояния сессий, фильтр, выбранный профиль, итоговая строка | Two-way `SearchQuery` и `SelectedProfile`, binding `VisibleProfiles`/`StatusText`; команды представления используют выбранный профиль из VM |
| `SessionViewModel` | Текущий раздел, активность вкладки, локализованный статус, доступность переподключения | Binding статуса и видимости reconnect; переключение раздела и polling используют свойства VM |
| `FileBrowserViewModel` | Путь, режим, сортировка, запрос, исходная/видимая выдача, выбор по POSIX-идентичности, история/scroll, поколение запросов, загрузка/ошибка/статус | Bindings обеих файловых коллекций, two-way поиска и строк состояния. Работающие view-прокси обращаются к VM вместо дублирующих полей; файловые действия получают `SelectedEntries` из VM |
| `FileItemViewModel` | Метаданные строки, отображаемое имя/расширение, cut-opacity, thumbnail | DataTemplate/DataGrid bindings; прежний вложенный `FileRow` удалён |
| `MonitorViewModel` | Snapshot, поиск, точная identity выбранного PID, форматирование метрик и недоступных значений, stale-state, данные графиков/сети/дисков | Two-way поиск, bindings таблиц/текстов и dependency-property графиков; прежний вложенный `ProcessRow` удалён |

`CommitNavigation` отвергает поздний ответ по поколению и меняет путь/историю только после успешной выдачи. Неудачный переход назад не сдвигает курсор истории. Выделение проверяется по точному POSIX-пути; исчезнувшие файлы и новый процесс с повторно использованным PID не наследуют прежнее выделение.

В code-behind остаются WPF-компоновка, фокус, меню/диалоги, OLE и clipboard, прокрутка/рамка выделения, связывание событий с пользовательскими действиями, декодирование изображений и оркестрация вызовов Core. Транспорт, секреты, доверие, SFTP и сбор/расчёт метрик остаются в независимых библиотеках без WPF. `ICommand`-обёртки вокруг каждого UI-события не вводились: модель состояния и bindings отделены, специфическое поведение представления остаётся в представлении.

Clipboard preparation и завершённый cut/paste используют номер последовательности Windows clipboard. Если во время ожидания пользователь скопировал другое, приложение не заменяет и не очищает новый буфер.

## Не засчитано без дополнительного испытания

- Реальный обмен с Windows Explorer (clipboard и OLE drag-and-drop) в обе стороны, hover-expand/scroll дерева и cross-tab drag; код реализован, но эти действия ещё требуется выполнить в реальном Explorer. Подготовка больших исходящих файлов до начала OLE — подтверждённая особенность реализации.
- Полная матрица мыши/клавиатуры/множественного выбора/рамки, перестановка вкладок и переподключение с переносом контекста; отдельные механизмы присутствуют, весь ручной набор не засчитан.
- Светлая/системная при светлой Windows и тёмная темы проверены на реальном экране. Высококонтрастная тема и полная матрица четырёх DPI ещё не засчитаны; WPF resize-тест не заменяет испытание DPI.
- Полная GUI-проверка всех файловых операций и отмены не подменяется сетевыми Core тестами. Результаты Core/нагрузочного стенда находятся в общей матрице ACCEPTANCE.md.
- Полный ручной GUI-прогон восьми видов выполнялся до выделения ViewModels. После рефакторинга повторены WPF/state/binding тесты, реальный опубликованный GUI с 10 000 файлов, системный CF_HDROP roundtrip и терминал; полный повтор всех ручных взаимодействий отдельно не засчитан.
- Чистая Windows 11 без установленных runtime и инструментов разработки требует отдельной машины/VM; текущая UI-проверка выполнена на рабочем Windows-хосте.

Ни один непроверенный пункт этой секции не объявляется успешной приёмкой.

## Итоговая проверка главным агентом

После MVVM-рефакторинга опубликованный EXE повторно показал настоящий каталог 10 000 файлов: 16 созданных строк, около 184 МиБ рабочего набора. Пройдены реальные Windows CF_HDROP → SFTP и SFTP → CF_HDROP с проверкой байтов/SHA-256 и opaque token, вызывая те же UI-команды Paste/CopySelection. Предыдущее содержимое буфера восстанавливалось с защитой от изменений пользователя. Это проверка настоящего системного формата и приложения, **не ручной Explorer/OLE drag-and-drop**.

В поставке проверен собственный Fixed WebView2 156.0.4314.58, реальные UTF-8/emoji и ANSI red. Проверена тёмная тема при 900×650, включая файловый список и открытое меню; светлая — при 1320×850. Нативная рамка учитывает тему через штатный DWM API. Приведённые выше списки внешней DPI/High Contrast и ручной приёмки остаются открытыми; окончательный статус — ACCEPTANCE.md.
