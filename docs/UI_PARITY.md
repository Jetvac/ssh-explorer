# Windows 11 UI parity — итерация 0.2

Исходная точка: `f15c2cd`, пользовательская 0.1.0 **не принята пользователем**. Код новой итерации не является доказательством визуальной приёмки. Сравнение выполняется по трём доступным изображениям из исходного сообщения: верхняя область Проводника, файловый Проводник и Диспетчер задач. Шесть изображений упомянуты в уточнении, но ещё три в доступном контексте отсутствуют; их содержание не восстанавливалось предположениями.

## Проверки, выполненные без управления рабочим столом

`SSHExplorer.UiTests.exe --resources-only`: реальные Application ресурсы и Fluent стили Light, Dark, System загружены/запечатаны; `Fluent.HC.xaml` загружен отдельно. **4 PASS**, ни одного окна не создавалось. Release-сборка выводится в `.tools/ui-v02`, а не поверх пользовательской поставки.

Применены официальные механизмы: [WindowChrome и native caption](https://learn.microsoft.com/en-us/dotnet/api/system.windows.shell.windowchrome), [Windows 11 Snap Layouts](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-snap-layout-menu), [WPF Fluent resource dictionaries](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/controls/control-styles-and-templates). Экспериментальный `ThemeMode` не используется.

## Единственный оператор GUI и незакрытая визуальная приёмка

Мышью, фокусом и окнами управляет только root. Специалист UI в этой итерации не использовал CUA/sky и не открывал окна. Поэтому новые screenshot/human results в таблице до реального прогона честно обозначены как ожидающие проверки.

Нужны сопоставимые before/after: Главная (пустая/с профилями), профиль, файлы с выбором и меню, терминал, процессы и производительность; несколько размеров, Light/Dark, High Contrast, 100/125/150/200%, другой монитор. Нативные maximize/restore/resize/system menu/Snap проверяются жестами Windows, а не наличием WindowChrome в коде. Пользовательскую оценку интерфейса можно закрыть только решением пользователя.
