# Нативное перетаскивание файлов — реализация и проверка

Дата: 03.11.2026. Документ относится к следующей итерации существующего WPF-приложения. Код обработчика, нативный COM-прогон и полный жест в настоящем Explorer — разные доказательства. Пользовательская приёмка всей матрицы **не завершена**; дальнейшие оконные испытания отложены по указанию пользователя.

## Исходящий перенос в Windows

`FileBrowserView.DragDrop.cs` фиксирует исходную сессию, пользователя, endpoint и точные пути **до** активации целевой вкладки. После порога движения вызывается нативный `Ole32.DoDragDrop`; перед ним нет скачивания содержимого, подготовки локальных файлов или переноса намерения в буфер обмена.

`NativeDragDrop/ShellVirtualDataObject.cs` реализует COM `IDataObject`:

- `FileGroupDescriptorW`: UTF-16 относительные имена, отдельные записи вложенных и пустых каталогов, атрибуты, доступное время изменения и 64-битный размер high/low.
- `FileContents`: индексированный `IStream`, без HGLOBAL всего содержимого файла.
- `Preferred DropEffect`: Copy для внешнего Windows-получателя.
- `SSHExplorer.RemoteFiles`: только непрозрачный 32-байтный токен для переноса внутри приложения.
- `CF_HDROP` для удалённых объектов **не объявляется**: несуществующие локальные пути не выдаются Windows.

Эти форматы соответствуют модели виртуальных файлов [Windows Shell Clipboard Formats](https://learn.microsoft.com/en-us/windows/win32/shell/clipboard). Реальная папка назначения и её конфликты остаются во владении операции Windows Explorer: стандартный источник виртуальных файлов не получает её полный путь. В общей очереди источник показывает «Выбранная папка Windows Explorer», а выбранное пользователем место сохраняет Shell.

## Потоки, COM и жизненный цикл

Первый CCW data object создаётся на отдельном MTA-потоке. Агрегируется Free-Threaded Marshaler; межпроцессные `GetData` и сетевые `IStream.Read` фактически выполнялись на MTA worker. Сеть не переносится на исходный WPF STA. Обоснование FTM и требования к thread safety: [CoCreateFreeThreadedMarshaler](https://learn.microsoft.com/en-us/windows/win32/api/combaseapi/nf-combaseapi-cocreatefreethreadedmarshaler).

`IDataObjectAsyncCapability.StartOperation` удерживает источник после завершения жеста, `EndOperation` завершает общую очередь. Синхронный получатель без этого необязательного интерфейса тоже поддержан: после чтения потоков принятие `Drop` завершает задание, а не отменяет его. Контракт асинхронного Shell-переноса: [Handling Shell Data Transfer Scenarios](https://learn.microsoft.com/en-us/windows/win32/shell/datascenarios#dragging-and-dropping-shell-objects-asynchronously).

Содержимое открывается лениво при `IStream.Read`. На операцию выделяется один принадлежащий исходной сессии SFTP-клиент; файловые потоки разделяют его сериализованный транспорт. Общая очередь ограничивает число выполняющихся передач. Управляемый блок COM-чтения не превышает 128 КиБ; весь файл в память не загружается.

Критический дефект отмены обнаружен реальным межпроцессным тестом: синхронный `SftpFileStream.Read` закреплённой SSH.NET 2026.0.0 использует `CancellationToken.None` внутри ожидания reader. Исправлено вызовом `ReadAsync(Memory<byte>, ownerToken)` и синхронным ожиданием только на COM MTA worker. Поведение проверено по [исходнику закреплённой версии SSH.NET](https://github.com/sshnet/SSH.NET/blob/2026.0.0/src/Renci.SshNet/Sftp/SftpFileStream.cs).

Закрытие вкладки отменяет связанное задание и закрывает его SSH-ресурсы. При отмене COM apartment сохраняется для получения `EndOperation`; если получатель аварийно завершился и этот callback не приходит, действует ограниченная двухсекундная grace-пауза, затем registry и MTA host освобождаются. Закрытие источника не завершает независимые серверные вкладки.

Linked CTS и регистрации callbacks освобождаются при **всех** исходах: успех, ошибка и отмена. Два GC-регрессионных теста подтверждают, что завершившийся external handle собирается при всё ещё живом источнике. Release-сборка не содержит вызовов диагностического `NativeTrace`: они исключены `Conditional(DEBUG)` и `#if DEBUG`; содержимое файлов и секреты не журналируются.

## Метаданные и различия получателей

Для обычной файловой выборки готовые дескрипторы строятся из уже загруженного снимка списка, без сети. Дерево каталогов читается в фоне. Если внутрипроцессный STA-получатель просит ещё не готовые рекурсивные метаданные, возвращается `E_PENDING` без `Failed`/`Cancel`; повторный запрос получает результат. Это договорённость для retry-capable STA-получателя, а не заявление, что каждый произвольный синхронный target умеет повторять запрос. Настоящий Explorer работает через межпроцессный MTA-путь, отдельно подтверждённый ниже.

Отрицательный/неизвестный размер обычного файла отклоняется с понятной причиной до преобразования в unsigned FILEDESCRIPTOR. Нулевой размер не обходит проверку: при фактическом чтении файл заново проверяется и открывается, включая исчезновение или изменение после выбора. Если объект сообщает размер 0, но отдаёт данные, пустая копия не объявляется успешной.

Несовместимое Windows-имя либо коллизия регистра предлагают безопасное имя. KeepBoth сохраняет соответствия в виртуальном `.sshexplorer-name-map.jsonl`; Skip исключает только этот объект, сохраняя остальной набор. Ограничения манифеста: 100 000 объектов, глубина 128, относительное имя FILEDESCRIPTORW до 259 UTF-16 code units. Symlink и специальные объекты не разыменовываются молча; для Windows требуется явный выбор допустимой цели.

## Внутренний и входящий перенос

`CanDropTo(data,path,keys)` — единый расчёт эффекта для списка, строки каталога, дерева и заголовка вкладки:

- Windows FileDrop → сервер: Copy в фактическую текущую папку/строку/узел.
- Внутри той же session ID: Move, Ctrl — Copy.
- Между разными session ID, включая один endpoint и разные учётные записи: Copy через клиент.
- Shift за пределами исходной сессии и Ctrl+Shift не подменяются другим действием: недопустимый курсор/отмена.
- Копирование в себя, собственный потомок и недоступная целевая сессия отклоняются до задания; ядро повторяет защиту.

Источник не перечитывается из SelectedTab после hover-активации цели. Токены хранятся в ограниченном (64) реестре WeakReference; живые CLR-объекты, пароли и ключи не сериализуются в OLE. Реализованы отдельная подсветка drop-target, прокрутка у края, раскрытие дерева по удержанию и активация вкладки по удержанию. После Move обновляется также живое исходное представление.

Явное Ctrl+C по-прежнему может подготовить существующие локальные файлы для Windows Clipboard. Этот отдельный сценарий **не используется** исходящим перетаскиванием и не служит его fallback.

## Реальный нативный прогон >2 ГБ

**Пройдено:** файл **2 148 532 224 байт** прошёл через настоящий межпроцессный `IDataObject → FILECONTENTS → IStream`, от SFTP до локального файла, без предварительной материализации. Манифест содержал 7 записей, включая вложенный/пустой каталог и реальный пустой файл; общий queue job завершён по `EndOperation`. Суммарные реальные bytes очереди с малым набором: **2 149 580 979**.

Независимый серверный `sha256sum` и локальный SHA256 совпали:

`F9C8466CDAC8F598A9DBBE999B62B47C2745C7B7368CD6BFCEE1B636368A9071`

Скорость около **12,2 МиБ/с**. WorkingSet64, измеряемый каждые 10 секунд: максимальное наблюдаемое значение **63 МиБ у source-процесса** и **35 МиБ у consumer-процесса**. Это наблюдаемые максимумы дискретных измерений, а не обещание точного OS peak между отсчётами. Результат подтверждает потоковую выдачу без роста памяти до объёма файла. Он **не является** измерением GUI/WebView2 и не подменяет ещё не выполненный большой жест в настоящем Explorer.

Доказательства: [полный лог](test-results/native-com-large.log), [размер/хеш/память](test-results/native-com-large-proof.json). После записи доказательств собственный серверный тестовый каталог и большая локальная копия удалены. Прежняя проверка >2 ГБ через обычную SFTP-очередь в этот результат не засчитывалась.

## Что остаётся для полной оконной приёмки

По указанию пользователя новые оконные испытания отложены. Не закрыты: полный incoming Explorer-жест для файлов и дерева, оба направления на tree/row/current folder во всех видах, Ctrl/Shift/Escape мышью, hover/autoscroll, различные пользователи одного узла, медленная сеть с отпусканием сразу над целью, UI-cancel после drop, конфликты/ENOSPC/отказы прав именно через настоящий Explorer, обрыв каждой стороны, memory/отзывчивость **всего GUI/WebView2/OLE-процесса** при >2 ГБ. Нативные консольные доказательства выше эти пункты автоматически не закрывают.

## Воспроизведение без окон

```powershell
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- --abi-only
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- isolated-config.json
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- --cancel isolated-config.json
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- --close-source isolated-config.json
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- --zero-gone isolated-config.json
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- --skip-name isolated-config.json
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- --metadata isolated-config.json
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- --lost-target isolated-config.json
dotnet run --project tests/SSHExplorer.NativeDrag.Tests -c Release -- --sync isolated-config.json
```

Конфигурация содержит endpoint, свежую тестовую учётную запись, SecretFile и независимо полученный ExpectedHostFingerprint; она находится вне Git. LargeFileBytes по умолчанию 0. Для большого прогона допускается исключительно разработческая команда существующего `truncate` в собственном тестовом каталоге и существующий `sha256sum`; в production-коде таких команд нет. Сборочный SDK требуется разработчику, не пользователю portable EXE.
