# Проверка безопасности 0.6: что приложение выполняет на сервере

Проверено 06.11.2026 по всему коду (`ExecuteAsync`, `ExecuteLongAsync`, `RunCommand`, ввод в терминал, SFTP-операции). Правило: всё, что меняет сервер или может прервать службы и процессы, выполняется только по действию пользователя и после подтверждения, в котором видно, что именно будет сделано. Автоматически выполняется только чтение.

## Автоматически (без действия пользователя) — только чтение

| Что | Команда | Когда |
|---|---|---|
| Проверка подключения | `printf`, `cmd /c ver`, `echo %COMSPEC%` | при подключении |
| Мониторинг «Диспетчер задач», «Сервер» | чтение `/proc`, `df`, `ip`; на Windows `Get-CimInstance`, `Get-Process` | пока раздел открыт |
| Оповещения | `df`, `systemctl --failed`; на Windows `Get-CimInstance` дисков и служб | раз в N минут, пока вкладка открыта |
| История метрик | тот же сборщик, что «Сервер» | раз в минуту для открытых вкладок и серверов с «Записывать в фоне» |
| Права для разделов | `id -u`, `sudo -n true` (без пароля, ничего не меняет) | при открытии Docker, файервола, cron |
| Проверка после перезагрузки | время загрузки, доступность SSH | после подтверждённой перезагрузки |

## Автоматически по настройке пользователя

| Что | Защита |
|---|---|
| Скрипты «при подключении» и по расписанию | создаёт и включает пользователь; импортированные из файла приостановлены; каждый автоматический запуск — событие в «Истории», ошибка — оповещение |
| Туннели «при подключении» | задаёт пользователь; открытый наружу туннель требует отдельного флажка; импортированные открытые наружу не запускаются сами |
| Свои метрики | команду пишет пользователь или берёт из шаблона (все шаблоны только читают); импортированные не запускаются до «Подтвердить»; sudo не добавляется |
| Возврат правил файервола и sshd по таймеру | часть подтверждённого изменения: о возврате сказано в вопросе |

## По действию пользователя с подтверждением

Перезагрузка и выключение · завершение процесса (SIGTERM/SIGKILL, с проверкой, что это тот же процесс) · действия со службами systemd и Windows · правила ufw и брандмауэра Windows · настройки sshd и ключи authorized_keys · удаление файлов · рекурсивная смена прав и владельца · удаление, пересоздание и изменение параметров контейнера · удаление задания cron · выполнение на нескольких серверах · синхронизация папок · поиск по содержимому.

**Добавлено этой проверкой** (раньше выполнялось без вопроса):

- Docker: «Запустить», «Остановить», «Перезапустить».
- cron: «Выключить» и «Включить» задание.
- «Скрипты»: «Запустить» — вопрос показывает первые строки скрипта.
- Скрипты, выполненные автоматически, теперь видны в событиях «Истории» (раньше — только при ошибке).

## Действия, явные сами по себе (без отдельного вопроса)

Ввод в терминал и «Фрагменты» (видно, что вводится; «Во все терминалы» — отдельный переключатель) · создание архива и распаковка (через окно с параметрами) · «Применить права» и «Применить владельца» к одному объекту · загрузка, переименование, создание папок · сохранение файла во внешнем редакторе (конфликты показываются) · команды обновления пакетов вписываются в терминал без Enter.
