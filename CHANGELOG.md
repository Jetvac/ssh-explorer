# История изменений

## 0.4.0 — в разработке

План — [docs/ROADMAP_0.4.md](docs/ROADMAP_0.4.md).

- **Экспорт и импорт серверов** («Главная» → «Экспорт», «Импорт» → «Из файла SSH Explorer»; правый щелчок по серверу → «Экспортировать…»). Файл `.sshx` содержит профили с туннелями, скриптами, параметрами Docker и закладками. Пароли по умолчанию не переносятся; по выбору они и секреты Docker шифруются парольной фразой (PBKDF2-SHA256 → AES-256-GCM) и при импорте сохраняются с защитой Windows этого компьютера. Дополнительно — доверенные ключи экспортируемых серверов, порядок панели и наборы правил файервола.
- **Оповещения**, пока приложение открыто: почти заполненный диск, служба в состоянии failed и ошибка автоматического скрипта на подключённых серверах — уведомлением Windows и в списке «Главная» → «Оповещения». Сообщается только о новом; порог и интервал — в «Параметры» → «Мониторинг».
- **Обновления пакетов** («Сервер» → «Обновления…»): сколько обновлений и какие из них — безопасности (apt, dnf, yum), возраст списков, нужна ли перезагрузка. Команда установки вписывается в терминал — пароль sudo вводится там.
- **«Копировать на другой сервер…»** в файловом менеджере: выбор открытой вкладки сервера и папки; данные идут через этот компьютер.
- **Раздел «Задания cron»**: задания словами с ближайшим запуском по времени сервера; добавить, изменить, выключить/включить, удалить; расписание проверяется по полям. Изменённый на сервере crontab не перезаписывается, прежний сохраняется.
- **Выполнение на нескольких серверах** («Главная» → «Выполнить на нескольких…»): команды или сохранённый скрипт на выбранных серверах параллельно, таблица результатов с выводом каждого сервера, повтор на неудачных, остановка. Только сохранённые данные входа; неподтверждённый ключ сервера не принимается.
- **Раздел «Защита SSH»**: ключи, которым разрешён вход (`authorized_keys`: добавить, удалить, слабые ключи), и **«Вход по ключу…»** — ключ Ed25519 создаётся на этом компьютере, открытый ключ ставится на сервер, вход проверяется новым подключением, и только потом профиль переключается на ключ.
- **Проверка настроек SSH-сервера** (`sshd -T`): вход по паролю, root, пустые пароли, попытки входа и др. Исправления — одной кнопкой с безопасным применением (`sshd -t`, перезагрузка без обрыва сеансов, проверка новым подключением, возврат). Отключить пароли нельзя, пока профиль сам входит по паролю.
- **Наборы правил файервола** («Файервол» → «Наборы правил…»): правила сервера сохраняются как именованный набор и применяются к другому серверу — добавляются только недостающие или сервер становится точной копией набора. Команды и доступ SSH видны заранее, применение — с проверкой нового подключения и возвратом. Наборы переносятся «Экспортом».
- Импорт: для каждого сервера — импортировать, пропустить, заменить существующий (его пароль сохраняется) или добавить копию; совпадения по адресу или имени по умолчанию пропускаются. Автоматические скрипты из файла приходят приостановленными, открытые наружу туннели не открываются сами, доверенный ключ из файла не заменяет другой уже доверенный.

## 0.3.1 — 2026-11-05

Файервол ufw с безопасным применением, SSH только через промежуточный сервер, настройка левой панели прямо в ней; модули переехали из «Параметров» в панель.

- **Файервол** (новый раздел навигации, ufw): правила с номерами в порядке проверки, состояние, политика по умолчанию, включение и выключение. Правило задаётся готовым вариантом (SSH, веб, базы данных, DNS) или вручную: действие (разрешить, запретить, отклонить, ограничить частоту), адрес или подсеть IPv4/IPv6, порт, список или диапазон портов, протокол, направление, интерфейс, комментарий, место в списке. Перед применением показаны точная команда ufw и то, пройдёт ли после неё ваше SSH-подключение. Подсказки о Docker (публикует порты в обход ufw) и о втором файерволе (firewalld).
- **Защита от потери доступа**: каждое изменение — один сценарий от root, который сначала сохраняет состояние ufw и ставит таймер возврата (systemd-run, иначе фоновый sleep). Затем приложение открывает **новое** SSH-подключение тем же маршрутом. Прошло — таймер отменяется. Не прошло — прежние правила возвращаются сразу (текущий сеанс ufw не обрывает). Связь потеряна — правила вернутся сами через 90 с. Отказ ufw на любой команде тоже возвращает всё как было.
- **«Доступ только через сервер»**: SSH к серверу остаётся открыт только для промежуточного сервера (по адресу, который видит сам сервер) и указанных вами адресов; правила, открывающие SSH другим, удаляются (каждое можно оставить), в конце ставится закрывающее правило для порта SSH. Если ufw выключен, слушающие сервисы можно оставить открытыми перед его включением. План, команды и расчёт доступа «для промежуточного» и «для остальных» видны заранее; применять можно только при подключении через промежуточный сервер, проверка идёт по этому маршруту.
- В профиле сервера «Подключаться через» — выбор сохранённого сервера из списка (кнопка «Выбрать…» рядом с полем), ручной ввод `пользователь@узел:порт` и цепочки остаётся.
- **Настройка левой панели сервера прямо в ней**: кнопка с шестерёнкой под списком разделов (или правый щелчок по панели) открывает редактор на месте — флажок показывает или скрывает раздел, порядок меняется перетаскиванием за ⠿, стрелками или Alt+↑/↓, «По умолчанию» возвращает обычный вид. Изменения сохраняются сразу и применяются ко всем открытым вкладкам; скрытый открытый раздел переключает вкладку на «Файлы», а «Файлы» скрыть нельзя. Правый щелчок по разделу — «Скрыть».
- **Модули Docker и «Скрипты» перенесены из «Параметров» в эту панель** и по умолчанию скрыты; скрытый модуль выключен (скрипты по расписанию не запускаются). Прежний выбор в «Параметрах» сохраняется.
- Диалог профиля: «Выбрать…» стоит рядом с полем промежуточного сервера, короткие поля — по два в строке, ровные отступы.
- Пользователь принял функционал и интерфейс 0.3.0 полностью ([ACCEPTANCE.md](ACCEPTANCE.md)).

## 0.3.0 — 2026-11-05

Подключения через агент и промежуточные узлы, импорт профилей, докачка, сравнение папок, архивы, поиск в файлах, службы systemd, журналы, разделение терминала, туннели, модули Docker и «Скрипты». В выпуск также входят все изменения интерфейса 0.2.0-beta.6, которая отдельно не публиковалась (раздел ниже). План и его выполнение — [ROADMAP_0.3.md](docs/ROADMAP_0.3.md).

- **Импорт из `~/.ssh/config`** («Главная» → «Импорт»): шаблоны `Host` с `*`, `?` и `!`, `Include`, кавычки, токены `%d %u %h %r %n` в `IdentityFile`; первое значение побеждает, как в OpenSSH. Предпросмотр: дубликаты и записи с ошибками не отмечены, у каждой строки — что не переносится. `ProxyCommand`, `LocalCommand` и блоки `Match` называются и никогда не выполняются; пароли не импортируются.
- **Вход через SSH-агент**: агент OpenSSH для Windows или `SSH_AUTH_SOCK` (pipe или Unix socket). Приватный ключ не попадает в приложение: подпись запрашивается у агента; RSA — `rsa-sha2-512/256`, также Ed25519 и ECDSA. Проверено настоящим `sshd` и `ssh-agent` в Linux CI.
- **Промежуточные узлы (ProxyJump)**: имя профиля или `пользователь@узел:порт`, до трёх через запятую. Один туннель на сессию для файлов, терминала, мониторинга и передач; ключ каждого узла подтверждается отдельно, ключ цели — по её имени. Пароль никогда не отправляется другому узлу: для входа по паролю промежуточный узел задаётся профилем со своим секретом. Проверено в Linux CI в сетевом пространстве, откуда цель напрямую недоступна.
- В профиле — поля «Промежуточные узлы» и «Группа»; строка состояния показывает маршрут.
- **Группы на «Главной»**: сворачиваемые заголовки «Прод · 2», порядок по имени, «Без группы» последней; без групп — прежний плоский список.
- **Импорт из PuTTY и WinSCP**: сохранённые сессии (реестр или WinSCP.ini), папки WinSCP становятся группами, ключи `.ppk` переносятся; пароли, туннели и не-SSH сессии не переносятся и названы в предпросмотре.
- **Докачка передач**: прерванная загрузка или скачивание продолжается кнопкой «Повторить» с проверенного места (источник не изменился, последние 64 КиБ совпадают); иначе — заново. Проверено на 96 МиБ по настоящему SFTP.
- **Параллельность и ограничение скорости** («Параметры» → «Подключения» → «Передачи»): 1–8 одновременных передач, общий лимит КБ/с, применяется сразу.
- **Занятые порты** («Производительность» → «Занятые порты»): протокол, адрес, порт, состояние, процесс, PID, пользователь; поиск по всем полям. Без прав root процессы других пользователей честно отмечены как скрытые.
- **Модуль Docker** (включается в «Параметры» → «Общие» → «Модули»): список контейнеров с поиском, запуск, остановка, перезапуск, удаление, журнал с режимом «Следить». «Параметры запуска»: образ, имя, политика перезапуска, сеть, порты, тома, команда и переменные окружения «ключ — значение»; параметры запоминаются по серверу, секретные значения шифруются (DPAPI) и не показываются. «Пересоздать с параметрами» — быстрый перезапуск по сохранённому. Значения env передаются через временный файл с правами 600 и в список процессов сервера не попадают. Долгие операции идут по отдельному SSH-подключению и не блокируют мониторинг.
- **Модуль «Скрипты»** («Параметры» → «Общие» → «Модули»): сохранённые для сервера последовательности команд — запуск вручную, при подключении, каждые N минут или ежедневно в ЧЧ:ММ (можно приостановить), «Остановиться на первой ошибке», таймаут, вывод и код последнего запуска. Текст передаётся файлом с правами 700 и в список процессов сервера не попадает; один скрипт не запускается внахлёст. Автоматический запуск работает, пока приложение открыто и сервер подключён; ошибка автоматического запуска показывается в строке состояния сервера.
- **Терминал**: Ctrl+C копирует выделение, Ctrl+V вставляет, выполняемую команду прерывает кнопка «Прервать» (^C); прежние клавиши возвращаются в «Параметры» → «Терминал». Кнопки «Копировать», «Вставить», «Прервать» в панели терминала.
- **Вкладки** закрываются средней кнопкой мыши; модули в навигации стоят после подразделов «Диспетчера задач».
- **Сравнение папок** (файлы → «Сравнить с папкой Windows…»): только на компьютере, только на сервере, различаются (с указанием, где новее), совпадают; по желанию — по SHA-256. Отмеченные различия загружаются или скачиваются через очередь передач после подтверждения; ничего не удаляется. Ссылки и специальные файлы не обходятся и перечислены.
- **Свойства**: владелец и группа — по имени или числу (имена берутся с сервера), биты setuid/setgid/sticky флажками, рекурсивное изменение подтверждается с числом объектов.
- **Пакетное переименование** («Переименовать несколько…»): шаблон `{name}`, `{ext}`, `{n}`, поиск и замена (в том числе регулярным выражением), регистр, предпросмотр; дубли, коллизии и недопустимые имена блокируют выполнение; обмен именами проходит через временные имена без перезаписи.
- **Просмотр текста** (F3): только чтение, кодировка и переводы строк как у редактора, ручной выбор кодировки, поиск, перенос строк; двоичные файлы и файлы больше 10 МиБ не открываются с объяснением.
- **Архивы** (файлы → «Сжать в архив…» / «Распаковать…»): tar.gz, tar.xz, tar.bz2, tar и zip программами сервера; форматы без нужной программы показаны недоступными. Архив пишется во временный файл и встаёт на место, только если имя свободно — существующий файл не заменяется. Перед распаковкой виден состав архива; по умолчанию — в новую папку, либо в текущую без замены существующих файлов; пути вне папки назначения («..», абсолютные) блокируют распаковку. Владелец из архива не применяется.
- **Поиск в файлах** (Ctrl+Shift+F): grep на сервере — текст или регулярное выражение, регистр, слово целиком, маски имён; двоичные файлы, `.git`, `node_modules` и подобные пропускаются. Результат открывается в просмотре на нужной строке или показывается в папке.
- **Службы** («Диспетчер задач» → «Службы»): службы systemd с состоянием и автозапуском, фильтр и поиск; запуск, остановка, перезапуск, перечитывание настроек и автозапуск — после подтверждения, от root, через `sudo -n` или от своей учётной записи (пароль не запрашивается). Для службы SSH — предупреждение о разрыве подключения. Внизу — журнал выбранной службы (`journalctl -u`, слежение).
- **Журналы**: «Следить за файлом (tail -F)» для файла на сервере (переживает ротацию) и журнал служб — фильтр текстом или `/регулярным выражением/`, до 20 000 строк. Команда на сервере завершается вместе с окном просмотра.
- **Разделение терминала**: до четырёх оболочек в разделе «Терминал» — «Разделить вправо», «Разделить вниз», «Закрыть» в шапке панели или Ctrl+Shift+D / E / W (работают и внутри терминала). Каждая панель — своя оболочка на своём подключении; при закрытии место занимает соседняя.
- **Туннели** (новый раздел навигации): сохранённые для сервера переадресации `-L` (порт на компьютере → адрес со стороны сервера) и `-R` (порт на сервере → адрес со стороны компьютера); открыть/закрыть, состояние, число соединений, «Открывать при подключении». По умолчанию слушают только `127.0.0.1`, другой адрес — только после явного подтверждения. Каждый туннель — отдельное SSH-подключение через те же промежуточные узлы и проверку ключа; занятый порт и отказ сервера объясняются.
- Исправлено: открытие «Служб» закрывало программу (раздел не был зарегистрирован в навигации сессии). Иконка «Служб» — векторная, в стиле остальных разделов.

## 0.2.0-beta.6 — отдельно не публиковалась, вошла в 0.3.0

Работа велась в ветке `claude/beta6-ui-rework`; соответствие каждого замечания, причины и статусы — в [UI_ITERATION_BETA6.md](docs/UI_ITERATION_BETA6.md).

- Вкладки: «Главная» больше не уходит за край после открытия первого сервера. Причина — устаревший extent прокрутки и отложенный `BringIntoView`. «+» стоит сразу за последней вкладкой; стрелки и список появляются только при переполнении.
- Строка пути включает ввод щелчком по свободной части, Ctrl+L и Alt+D работают из таблицы, дерева, поиска и панели команд. Breadcrumb-кнопки по-прежнему переходят по пути.
- Заголовок окна: собственные Minimize/Maximize/Close в строке вкладок, без разрыва с системной областью. Сохранены Snap Layouts (`HTMAXBUTTON`), drag, двойной щелчок, Alt+Space, красный Close, неактивное состояние и High Contrast.
- Иконки:
  - именованный каталог: 33 проверенных глифа Segoe Fluent и 22 собственных вектора (включая «Параметры»);
  - исправлен «телефон» вместо «Мелких значков»;
  - новый знак приложения (SVG и ICO 16–256) в EXE, окнах и «О приложении»;
  - [лист иконок](docs/design/icon-sheet.png) и [происхождение](docs/design/ICONS.md).
- «Параметры» разбиты на разделы. Версия и диагностика перенесены в «О приложении», числа показываются с единицами. «Передачи» получили пустое состояние, колонки прогресса, скорости и остатка, панель деталей и действия по состоянию.
- Графики рисуют линию для медленных, но успешных замеров. Разрыв ставится только при сбое, паузе или реальной потере непрерывности. Время монотонное, история ограничена временным окном, а не 120 точками. Добавлены оси, текущее значение и значение под курсором.
- Мониторинг: системные метрики отделены от процессов. Сбор для графиков — 22 мс вместо 3,3 с (замер на 369 процессах), опрос процессов — в 30 раз быстрее.
- Новый раздел «Сервер»:
  - сведения о системе, процессоре, памяти, сети, доступе и хранилищах;
  - обновить, переподключиться, открыть терминал;
  - перезагрузка и выключение с определением прав без пробного запуска, явным подтверждением и одной командой без повторов;
  - проверка перезагрузки по смене `boot_id`, честный «неизвестный результат». SSH-пароль не используется как пароль sudo.
- Сортировка щелчком по заголовку во всех таблицах: «Главная», сеть, диски, хранилища, передачи, документы. Ключи типизированные, неизвестное в конце, порядок сохраняется для каждой таблицы. Файлы помнят сортировку между запусками.
- Поставка:
  - без отчётов разработчика, лишних языковых ресурсов WPF и XML-документации пакетов;

### Перетаскивание и буфер обмена

- Для сервер → Windows добавлен нативный OLE-источник виртуальных файлов `FILEDESCRIPTORW`/`FILECONTENTS`, потоковый `IStream` и `IDataObjectAsyncCapability`. Экспорт больше не требует предварительного полного скачивания и повторного жеста. Данные читаются с ограниченным буфером через выделенный MTA-host.
- Источник копирования Windows → сервер — реальные Windows файловые объекты. Межсерверное копирование, перемещение в пределах сессии, Ctrl/Shift, запрет self/descendant и недоступные назначения проверяются общими правилами назначения.
- Подсветка цели, hover переключения вкладки, очистка drop-состояния и обновление исходного вида после перемещения согласованы. Payload вкладок и файлов использует непрозрачные raw-токены со слабыми ссылками, без сериализации CLR-объектов.
- `Ctrl+C` по-прежнему готовит локальные `CF_HDROP` в `TransferCache`; это отдельный механизм. Защита sequence-number предотвращает замену более нового содержимого системного буфера после долгого скачивания.
- Живо проверены небольшие файлы между вкладками A↔B и перемещение в строку папки внутри сессии. Полная Explorer/large/cancel матрица и сохранность источника требуют отдельной приёмки; COM ABI-тест не выдаётся за доказательство живого drag/drop.
